# C3M1 固件架构与硬件实测笔记

本文档记录 `c3m1-firmware` 在 C3M1 (C3MarkI) 量产硬件上的核心软件架构、关键时序设计与实机排坑经验，便于后续迭代与维护。

---

## 1. 常驻 RAW 微单化架构（Always-RAW Mirrorless Viewfinder）

### 1.1 为什么放弃“QVGA RGB565 预览 ↔ VGA RAW 拍照”双模式切换？
原厂与早期固件在取景时让 OV7725 输出 QVGA RGB565，按下快门后再发 SCCB 软复位并重载 `ov7725_init_reg_tbRAW`、丢弃 5 帧过渡帧、拍完再软复位切回 QVGA。这带来三个固有缺陷：
1. **严重快门时滞（0.4 ~ 1.5s）**：按下快门到真正锁帧跨越模式切换与多帧丢弃，手持移动时成片与取景错位。
2. **预览与成片曝光脱节**：QVGA RGB565 与 VGA RAW 的时钟/行频/片内 DSP 不同，无法实现真正的所见即所得（WYSIWYG）曝光模拟。
3. **4X 对焦放大卡顿**：需要重写 OV7725 窗口寄存器并丢帧。

### 1.2 常驻 RAW + DMA1 流水线设计
现行固件开机初始化一次后，**OV7725 永久运行在 `644×480` 8-bit `GRBG` RAW 模式**（`COM7=0x13`, `COM3=0xD0`, `COM4=0x81` 6× PLL, `CLKRC=0x00` = `18 MHz` PCLK / **45 fps** / `22,959 行/秒` / `20.9 ms` 卷帘扫描，`COM2=0x01` 柔和驱动防 FPC 排线振铃）：

- **实时 LUT 解马赛克**：
  - Flash 中存放 256 字节标准 IEC 61966-2-1 sRGB OETF 曲线表 `s_srgb_lut[256]`（暗部采用线性斜率避免 8-bit 阴影噪点被放大）。
  - SRAM 中维护三张零等待 16-bit 预移位 RGB565 查表 `s_lut_r/g/b[256]`（共 `1.5 KB`），一次性融合 `BlackLevel=2` 扣除、预览白平衡增益、慢门数字补偿增益、sRGB Gamma 与 RGB565 位打包；单像素合成仅 `lr[r] | lg[g] | lb[b]`。
  - **1X 预览（`320×110` 逐行双倍 → `320×220`）**：偶数 RAW 行仅读取 320 个 `R` 字节（跳过 `G0` 时并行回写上一像素），奇数 RAW 行读取 `(B, G1)` 并在 SRAM 拼出 640 字节大端 RGB565 行缓冲；随后由 `DMA1_Channel1`（MEM2MEM，`CMAR -> &LCD->LCD_RAM`）在后台连续发送两行，同时 CPU 并行跳过下 2 行 RAW 数据并解码下一行。单帧刷屏时间压缩至 **~26–28 ms**，彻底消除慢刷屏引发的横切撕裂，快门档实测可达 **15–20 fps**。
  - **4X 对焦放大（原生 `1:1` 中心 `320×220`）**：跳过前 130 行 RAW（偶数行保持 `GRBG` 相位不变），在双行 `322 B` 缓冲上做逐像素 `1:1` 解马赛克并同样通过 `DMA1` 双缓冲流式写屏，零 SCCB 写入、瞬时切换。
- **预览 AWB 与软件闭环 AE**：
  - 刷屏过程中每隔 4 行 × 4 列抽样约 4,400 像素（极低开销），计算 Gray-World 白平衡并一阶 IIR 平滑更新 `s_lut_r/b`；**AWB 仅作用于 LCD 预览查表，绝不修改传感器寄存器或 DNG 原始像素**。
  - `AUTO` 快门（拨盘 `15`，底栏显示 `SA:`，范围 **`1/30000s ~ 1/50s`**）与 `AUTO` ISO（`g_iso_idx == 0`，底栏显示 `IA:`，范围 `100 ~ 1600`）均由每 2 帧运行一次的软件闭环 AE（±20% 防抖死区 + 75% 阻尼步进 + 高光保护）驱动。双自动模式采用 4 段微单 **P 曲线**：
    1. **强光区**（`1/30000 ~ 1/125s`，最低 `1` 行）：锁定 `ISO 100` 保最大动态范围与正午高光余量；
    2. **中光斜坡区**（`1/125 ~ 1/60s`）：快门与 ISO 对角协同渐变（同步降至 `1/60s`、拉升 `ISO 100 → 400`）；
    3. **暗光区**：守住 `1/60s` 安全快门（维持 60 fps 传感器扫描）拉升 `ISO 400 → 1600`；
    4. **暗光下限区**：锁定 `ISO 1600`，快门缓降至 `1/50s`（`612` 行，兼顾手持安全快门与 15–16F 取景流畅度）。

## 2. 16 档快门拨盘、零时滞快门与慢门 12fps 预览

### 2.1 拨盘映射（`PF6~PF9` BCD）
| 拨盘值 | 显示档位 | 预览传感器状态 | 拍照执行路径 |
| :--- | :--- | :--- | :--- |
| `0..8` | `1/8000 ~ 1/50` | `CLKRC=0x00`（60~43 fps），**精确拍照曝光** | **真零时滞（0~17 ms）**：不写传感器、不丢帧，直接写已锁存 FIFO 帧 |
| `9` | `1/25` | `CLKRC=0x00`（`1344` 行 / 40 ms），**精确拍照曝光** | **真零时滞（0~40 ms）**：直接锁存写出 |
| `10..14` | `1/8, 1/4, 1/2, 1s, 2s` | `CLKRC=0x00`，`DM_LN=0`、`AEC=500`（60 fps 传感器 → **稳跑 16F**），由硬件 `GAIN`（最高 31×）+ 数字 LUT（最高 4×）补偿预览亮度 | 居中显示 `EXPOSING...`，VSYNC 边界原子切入 `CLKRC=0x01`（`15,306 行/秒`）+ 真实 `DM_LN/AEC` + 用户低 ISO（无软复位），曝光 1 帧后在 VBLANK 提前锁帧，同步切回 `CLKRC=0x00` 预览 |
| `15` | `AUTO` | `CLKRC=0x00`，4 段 P 曲线软件闭环 AE（`1..612` 行 = `1/30000 ~ 1/50s`），底栏显示 `SA:1/xxx` | **真零时滞（0~22 ms）**：直接锁存写出当前曝光帧 |

> **为什么慢门 `10..14` 拍照切 `CLKRC=0x01`？**  
> 在 `COM4=0xC1, CLKRC=0x00`（实测 30,612 行/秒）下，`2s` 需要 ~61,224 行，接近 16-bit `AECH/AEC` 与 `DM_LNH/DM_LNL` 上限；拍照瞬间将 `CLKRC` 切至 `0x01`（15,306 行/秒，保持 `COM4=0xC1` 不断锁 PLL），`2s = 30,612` 行安全落在 16-bit 范围内；又因 VSYNC_B 后有效 480 行仅需 ~31 ms 即写完进 AL422B（随后进入 `HREF=0` 的长 VBLANK），固件在 `65 ms` 处提前关闭 `WEN` 锁死帧并切回高速预览，使长曝总等待耗时仅为 `1× 快门时间 + ~0.18s`。

## 3. 已验证的关键硬件问题与修复原理

### 3.1 AL422B 慢卡写 DNG 断层撕裂（已实机验证根除）
- **根因**：旧流程先执行 `f_open()` + `f_write(592)` + `stmflash_write()`（STM32F103 单 Bank Flash 页擦写会挂起 CPU/中断 20–40 ms），再等 `g_vsync_state == 2`。在慢速 SD 卡上，该延迟把下一帧推入正在写入的 AL422B 384 KB 环形缓冲区导致指针回绕覆盖，形成横向错位拼接断层。
- **修复**：`ov7725_camera_output()` 入口处**先等待 `g_vsync_state == 2`（`FIFO_WEN = 0` 硬件锁死 FIFO）**，再打开文件、写头与更新 Flash 快门计数；同时加宽 `exti.c` 中 `/WRST` 低脉冲宽度确保写指针可靠归零。

### 3.2 成片左右镜像与 Bayer 排列（已实机验证根除）
- **根因**：原厂 RAW 配置 `COM3=0x50`（仅水平镜像）叠加 DNG `Orientation=3`（180° 旋转），合成净变换为“仅垂直翻转”，导致成片左右镜像。
- **修复**：OV7725 硬件直接配置 `COM3=0xD0`（`VFLIP=1, HMIRROR=1`），DNG 头改为 `Orientation=1`（正向）+ 实测验证的 `CFAPattern=GRBG (01 00 02 01)`。

### 3.3 顶板 `LED1 (PD9)` 常亮问题（已实机验证根除）
- **根因**：顶板原理图中 `LED1` 阳极接在 **`VCC5.0`**（非 3.3V），`PD9` 设为推挽输出高电平（3.3V）时 LED 两端仍有 `1.7V` 压差导致取景期间微亮/常亮。
- **修复**：利用 STM32F103 `PD9` 的 5V 容忍特性，在 `Core/Src/gpio.c` 将其改为 **`GPIO_MODE_OUTPUT_OD`（开漏输出）**：输出 `1`（高阻）彻底熄灭，输出 `0`（接地）点亮。状态定义：取景全灭 / 曝光与锁帧常亮 / 写 SD 卡 80 ms 闪烁 / 出错快闪 3 次。

### 3.4 MicroUSB 复用 SWD 烧录口（避坑）
- 主板 `USB1` 脚位：`Pin1=VCC3.3`、`Pin2=SWDIO`、`Pin3=SWCLK`、`Pin4=NRST`、`Pin5=GND`。
- **禁止接电脑 5V USB**（会烧毁 3.3V 域芯片）；**禁止使用 OTG MicroUSB 线**（`Pin4 ID` 与 `GND` 短接会永久拉低 `NRST`，导致 OpenOCD 报 `Halt timed out` / `DHCSR=0x02010001`）。使用普通 4 芯非 OTG 线悬空 `NRST` 配合 `reset_config none` 即可稳定烧录。

### 3.5 无 RTC 硬件与时间戳约定
- 机身电源开关 `SW4` 硬切断电池正极，`VBAT` 接 `VCC3.3`，`PC14/PC15` 悬空无 32.768 kHz 晶振，硬件无 RTC。
- FatFs 文件修改日期（`FATFS/Target/ffconf.h`）配置为 `2026-12-26`，DNG 内嵌 `DateTime` 标签（Tag `0x0132`）配置为 `"2026:08:17 00:00:00"`。

### 3.6 消除 1~2 行偶发错色（`CLKRC` 差量缓存 + `COM4=0x81` 18 MHz 裕量）
- **根因**：
  1. OV7725 的 `CLKRC (0x11)` 寄存器不经 VSYNC 阴影缓冲，在 AL422B 录帧中途重写会打乱分频相位；
  2. `COM4=0xC1`（8× PLL / `24 MHz` PCLK）紧贴 OV7725 12 MHz/路共享 ADC 上限，且 `COM2=0x03`（4× 强驱动）在未端接 FPC 排线上产生过冲振铃，导致偶发 1~2 行像素错色。
- **修复**：
  1. `ov7725_apply_always_raw_preview()` 增加寄存器差量缓存，且 `raw_preview_update_ae_awb()` 移至 `g_vsync_state = 0` 之前执行（冻结 FIFO 期间完成 SCCB 通信）；
  2. 将 `COM4` 回调至 `0x81`（6× PLL / `18 MHz` PCLK / 45 fps，较 ADC 上限留出 25% 裕量）、`COM2` 恢复柔和默认 `0x01`，保持全快门/慢门档稳跑 **15F** 且画面干净无错色。
