# C3M1 固件架构与硬件实测笔记

本文档记录 `c3m1-firmware` 在 C3M1 (C3MarkI) 量产硬件上的核心软件架构、关键时序设计与实机排坑经验，便于后续迭代与维护。

---

## 1. 常驻 RAW 微单化架构（Always-RAW Mirrorless Viewfinder）

### 1.1 为什么放弃“QVGA RGB565 预览 ↔ VGA RAW 拍照”双模式切换？
原厂与早期固件在取景时让 OV7725 输出 QVGA RGB565，按下快门后再发 SCCB 软复位并重载 `ov7725_init_reg_tbRAW`、丢弃 5 帧过渡帧、拍完再软复位切回 QVGA。这带来三个固有缺陷：
1. **严重快门时滞（0.4 ~ 1.5s）**：按下快门到真正锁帧跨越模式切换与多帧丢弃，手持移动时成片与取景错位。
2. **预览与成片曝光脱节**：QVGA RGB565 与 VGA RAW 的时钟/行频/片内 DSP 不同，无法实现真正的所见即所得（WYSIWYG）曝光模拟。
3. **4X 对焦放大卡顿**：需要重写 OV7725 窗口寄存器并丢帧。

### 1.2 常驻 RAW + AL422B 先锁帧后读与 DMA1 流水线设计
现行固件开机初始化一次后，**OV7725 永久运行在 `644×480` 8-bit `GRBG` 片内 10-bit Gamma 压扩 RAW 模式**（`COM7=0x01`, `DSP_Ctrl1=0x87`, `DSP_Ctrl4=0x02`, `COM13=0xE6`, `COM3=0xD0`, `COM4=0x81` 6× PLL, `CLKRC=0x00` = `18 MHz` PCLK / **45 fps** / `22,959 行/秒` / `43.56 µs/行` / `20.9 ms` 卷帘扫描，`COM2=0x01` 柔和驱动防 FPC 排线振铃）：

- **单基址零溢出 SRAM 查表与 Cortex-M3 `USAT` 色度增强**：
  - Flash 中存放 256 项 12-bit 反 Gamma 表 `s_inv_gamma_12[256]` 与 IEC 61966-2-1 sRGB OETF 曲线表 `s_srgb_lut[256]`。
  - SRAM 中维护一块连续 `768 B` 零等待 6-bit 查找表 `s_lut_rgb6[3][256]`（`[0..255]=R6`、`[256..511]=G6`、`[512..767]=B6`，一次性融合动态黑电平、预览白平衡增益、慢门数字补偿增益与 12-bit 插值 sRGB OETF），解马赛克热循环通过单一基址指针配合 `| 0x100` / `| 0x200` 索引，实现 **0 Flash 常量池加载、0 栈溢出**；片上用代数等价式 `(7c - 3y) / 4` 配合 Cortex-M3 单周期 `USAT Rd, #5/#6, Rn, ASR #3/#2` 与 32-bit `REV16` 双像素打包完成 1.75× 色度增强，同时零拷贝输出 `G6` 行缓冲供 2D 峰值对焦复用。
- **AL422B 严格先锁帧后读取（C3M1 硬件硬约束，禁用边写边读）**：
  - 固件曾于 `ba7e287` 验证过 AL422B 边写边读（`g_vsync_state == 1` 起跑，读屏实测可推高至 1X 关矫正 `12 fps` / 开矫正 `10 fps` / 4X `8 fps`），但实机排查发现在 1X 关/开矫正与 4X 下均会偶发单帧蓝色错色（局部小块 / 中下部 / 整屏，底栏 HUD 正常；加宽 `RCLK` `__NOP()` 无效，单变量关闭边写边读后 100% 消失）。
  - 对照芯片手册（`AL422B.pdf`）与主板原理图（`主板电路图.pdf`），确认存在三条不可绕过的硬件约束：
    1. **`/RE` 接地导致无法合规做不规则并发读（`AL422B.pdf` p.7 §7.4、p.16–17 §8.3.1 `AL422-16`）**：主板 `U3 (AL422B-PBF)` Pin 24 (`/RE`) 直接接地，STM32 无法保持 `RCK` 持续运行（`T_RC <= 1000 ns / ≥1 MHz`）并用 `/RE` 门控，只能停停走走地突发翻转 `RCK`（手册 `AL422-16 Incorrect` 时序）。写空闲（`/WE = 1`）时由持续 18 MHz `WCK` 单独驱动内部 DRAM 刷新故完全稳定；一旦 `/WE = 0` 并发写读，不规则 `RCK` 会与写端口/刷新周期争抢内部 `Timing Generator & Arbiter`（p.13 `AL422-03`）。
    2. **128 字节内部 SRAM Cache 与禁止新旧帧混读规则（`AL422B.pdf` p.13–14、p.17 §8.3.2）**：读指针须全程严格滞后写指针 `128 ~ 393,247` 周期且单次 `/RRST` 周期内不可混读旧帧/新帧数据；而 VBLANK 期间 `/WE = 1` 下发的 `/WRST` 会延迟到首行 `HREF` 才生效（p.12 `AL422-15`、p.14 §8.1），任何 `DM_LN` 哑行或起跑余量波动都会触发手册注明的连续错读（*"some amount of consecutive unexpected data"*）。
    3. **主板 `VCC3.3` 瞬态余量偏紧（`主板电路图.pdf`）**：`Q2 (AMS1117-3.3V)` 输出电容 `C34` 仅 `1 µF`，同时供给 STM32 + AL422B（33–50 mA）+ FSMC 24-pin FPC；三路高速总线并发切换时电源/地瞬态抖动极易在后半帧写入窗口干扰 18 MHz 写采沿。
  - 因此现行固件严格坚持等第 2 次 VSYNC（`g_vsync_state == 2`，EXTI 硬件拉低 `WEN = 0`）后再调用 `fifo_prepare_read()` 读屏，保证写帧期间 `RCLK` 与 FSMC 总线完全静默、100% 零错色；帧率全部通过安全读屏阶段的纯软件 CPU/DMA 热循环压榨提升。
- **1X 与 4X DMA1 双缓冲流水线**：
  - **1X 全视野（`320×120` 逐行双倍 → 全屏 `320×240`）**：首行对预读 `R` 字节，随后每发送偶数液晶行 `y0` 的后台 DMA 期间，CPU 同步执行 `fifo_skip_bytes(2×644)` + 下一行对 `fifo_read_r_320()`，使 `y0` DMA 等待归零；发送奇数行 `y1` 期间并行完成 `(B, G1)` 解马赛克与 2D 峰值对焦，底部 20px 半透明 HUD 与直方图均在线合入行缓冲零闪烁输出，每 8 行对抽样 1,200 像素驱动 AWB/AE/直方图。
  - **4X 对焦放大（原生 `1:1` 中心 `320×240`）**：跳过前 120 行 RAW（偶数行保持 `GRBG` 相位不变），在双行 `322 B` 缓冲上做逐像素 `1:1` 解马赛克并通过 `DMA1` 双缓冲流式写屏，零 SCCB 写入、瞬时切换。
- **预览 AWB 与软件闭环 AE**：
  - 刷屏过程中抽样计算 Gray-World 白平衡并一阶 IIR 平滑更新 `s_lut_rgb6`；**AWB 仅作用于 LCD 预览查表，绝不修改传感器寄存器或 DNG 原始像素**。
  - `AUTO` 快门（拨盘 `15`，底栏显示 `SA:`）与 `AUTO` ISO（`g_iso_idx == 0`，底栏显示 `IA:`）由每 2 帧运行一次的软件闭环 AE 驱动，并延后至 `g_vsync_state == 1`（VBLANK 消隐期）原子写入防跨帧闪屏。

### 1.3 实时取景延迟（1X vs 4X）、快门延迟与推荐拍摄流程

#### (1) 实时监看刷新延迟（Motion-to-Photon，45 fps 传感器基准）
设 VSYNC #0 上升沿为 $`t = 0`$，传感器中心行（第 240 行）在 $`t_{\text{exp}} \approx 10.5\text{ ms}`$ 完成曝光并写入 FIFO，VSYNC #1（$`t = 22.22\text{ ms}`$）锁帧后启动读屏，屏幕中心（第 120 行）在 $`t_{\text{lcd}} = 22.22 + T_{\text{paint}} / 2`$ 刷入 ST7789V3 GRAM：
- **刚刷新瞬间最小延迟**：$`L_{\min} = t_{\text{lcd}} - t_{\text{exp}}`$
- **下次刷新前最大延迟**：$`L_{\max} = L_{\min} + T_{\text{period}}`$
- **画面中心平均监看延迟**：$`L_{\text{avg}} = L_{\min} + T_{\text{period}} / 2`$（叠加 ST7789V3 自身 60 Hz 面板刷新平均约 `+8 ms`）

| 取景模式 | 单帧绘制耗时 $`T_{\text{paint}}`$ | 帧周期 $`T_{\text{period}}`$ / 实测帧率（含非 0 `LENS VIG`） | 中心刷新延迟 $`L_{\min} \sim L_{\max}`$（均值，不含面板 ~8 ms） |
| :--- | :---: | :---: | :---: |
| **`1X`（`INCAM DISTORT = OFF`）** | `~55–66 ms` | `88.9–111.1 ms` / **`9–11 fps`** | `~42 ~ 135 ms`（均值 `~88 ms`） |
| **`1X`（`INCAM DISTORT = ON`）** | `~70–85 ms` | `100–111.1 ms` / **`9–10 fps`**（优化前 `8 fps`） | `~45 ~ 145 ms`（均值 `~95 ms`） |
| **`4X`（原生 `1:1` 中心放大）** | `~88–105 ms` | `111.1–133.3 ms` / **`8 fps`**（优化前 `7 fps`） | `~55 ~ 170 ms`（均值 `~110 ms`） |

#### (2) 快门延迟分解（按键物理触发 → 成片中心曝光）
为将快门响应压缩至 45 fps 硬件物理极限，固件实施四级协同优化：
1. **前沿瞬时触发 + 释放侧消抖（`Drivers/BSP/KEY/key.c`）**：`KEYSHOT` 无长按复用，按下低电平经 ~10 µs 抗干扰复查即刻触发 `BTN_EVT_SHOT`（消除原 25 ms 按下消抖）；消抖移至松手侧，须连续保持高电平 `30 ms` 后重新上膛，防止触点弹跳误连拍。
2. **取景刷屏中途 2–3 ms 快速截断（`Core/Src/main.c`）**：`1X` 每 4 行对（`~2 ms`）、`4X` 每 8 行（`~3 ms`）轮询快门引脚；一旦触发立即中止剩余刷屏。
3. **立即武装下一 VSYNC**：截断时原子将 `g_vsync_state` 从 `2` 清零为 `0`，立即武装下一 VSYNC 锁帧（时差 `10 ~ 33 ms`，均值 `~21 ms`）。同时移除拍前重复的 `c3m1_cfg_save()`（消除改 ISO 后首张 15–30 ms SD 写入阻塞）。
4. **定格画面与落盘成片严格一致（`0 ms` 差）**：`camera_capture_one_to_fifo()` 在 `g_vsync_state == 2` 锁死 FIFO 后，先调用 `camera_show_latched_preview()`（全屏 `320×240` + 50% 半透明 `SAVE` 底栏与 3×3 构图线，`~25 ms`，零额外 RAM）将**同一锁存帧**刷到屏幕再写 SD 卡，彻底消除快动目标下“屏幕定格帧 ≠ 成片”的错位与底栏闪黑。

| 拍摄档位 | 按键触发 | 刷屏截断 | 传感器曝光对齐 | 端到端快门延迟（按下→成片中心曝光） |
| :--- | :---: | :---: | :---: | :---: |
| **常规快门 `1/8000 ~ 1/50` & `AUTO`** | `~0.01 ms` | `0–2 ms` (1X) / `0–3 ms` (4X) | 下一 VSYNC 中心曝光（`10 ~ 33 ms`） | **`10 ~ 33 ms`（均值 `~21 ms`）** |
| **慢门 `1/25 ~ 2s`（及暗场慢速 `AUTO`）** | `~0.01 ms` | `0–3 ms` | VSYNC 切 `CLKRC=0x01`（`22–44 ms`）+ 完整慢门曝光 | `22 ~ 44 ms + 1× 快门时间` |

#### (3) 推荐工作流：4X 对焦 → 1X 监看拍摄
- **对焦阶段用 `4X`**：跳过上下各 120 行、原生 `1:1` 像素无抽行显示并叠加高灵敏度 2D 峰值，手动拧镜头的合焦判定最精准。
- **监看与抓拍阶段切回 `1X`（`INCAM DISTORT = OFF`）**：短按 `4X` 零 SCCB 写入瞬时切回 `1X`，视野完整、刷新更快且快门截断响应最快（`<= 2 ms`），最适合抓拍移动物体与决定性瞬间。

## 2. 16 档快门拨盘、零时滞快门与慢门高速预览

### 2.1 拨盘映射（`PF6~PF9` BCD）
| 拨盘值 | 显示档位 | 预览传感器状态 | 拍照执行路径 |
| :--- | :--- | :--- | :--- |
| `0..8` | `1/8000 ~ 1/50` | `CLKRC=0x00`（45 fps，`DM_LN=0`），**精确拍照曝光** | **极限零时滞（`-10 ~ +33 ms`，均值 `~12–15 ms`）**：不写传感器、前沿触发、2–3 ms 截断刷屏，直接锁存并回显同一 FIFO 帧后写卡 |
| `9..14` | `1/25, 1/8, 1/4, 1/2, 1s, 2s` | `CLKRC=0x00`，`DM_LN=0`、`AEC=500`（45 fps 传感器 → 全档位保持与常规快门一致的取景帧率），由硬件 `GAIN`（最高 31×）+ 数字 LUT（最高 4×）补偿预览亮度 | VSYNC 边界原子切入 `CLKRC=0x01`（`11,480 行/秒`）+ 真实 `DM_LN/AEC` + 用户低 ISO（无软复位；`1/8..2s` 居中显示 `EXPOSING...`），曝光 1 帧后在 VBLANK 提前锁帧、回显同一锁存帧写卡并同步切回 `CLKRC=0x00` 预览 |
| `15` | `AUTO` | `CLKRC=0x00`，4 段抗频闪 P 曲线软件闭环 AE（`1..459` 行常规快门，或按 `MIN AUTO SHT` 扩展慢门），底栏显示 `SA:1/xxx` | 常规快门下同 `0..8` **极限零时滞（`-10 ~ +33 ms`）**；暗场慢于 `1/50` 时自动走单帧原子慢门 |

> **为什么慢门 `10..14` 拍照切 `CLKRC=0x01`？**  
> 在 `COM4=0xC1, CLKRC=0x00`（实测 30,612 行/秒）下，`2s` 需要 ~61,224 行，接近 16-bit `AECH/AEC` 与 `DM_LNH/DM_LNL` 上限；拍照瞬间将 `CLKRC` 切至 `0x01`（15,306 行/秒，保持 `COM4=0xC1` 不断锁 PLL），`2s = 30,612` 行安全落在 16-bit 范围内；又因 VSYNC_B 后有效 480 行仅需 ~31 ms 即写完进 AL422B（随后进入 `HREF=0` 的长 VBLANK），固件在 `65 ms` 处提前关闭 `WEN` 锁死帧并切回高速预览，使长曝总等待耗时仅为 `1× 快门时间 + ~0.18s`。

## 3. 已验证的关键硬件问题与修复原理

### 3.1 AL422B 慢卡写 DNG 断层撕裂（已实机验证根除）
- **根因**：旧流程先执行 `f_open()` + `f_write(592)` + `stmflash_write()`（STM32F103 单 Bank Flash 页擦写会挂起 CPU/中断 20–40 ms），再等 `g_vsync_state == 2`。在慢速 SD 卡上，该延迟把下一帧推入正在写入的 AL422B 384 KB 环形缓冲区导致指针回绕覆盖，形成横向错位拼接断层。
- **修复**：`ov7725_camera_output()` 入口处**先等待 `g_vsync_state == 2`（`FIFO_WEN = 0` 硬件锁死 FIFO）**，再打开文件、写头与更新 Flash 快门计数；同时加宽 `exti.c` 中 `/WRST` 低脉冲宽度确保写指针可靠归零。

### 3.2 成片左右镜像与 Bayer 排列（已实机验证根除）
- **根因**：原厂 RAW 配置 `COM3=0x50`（仅水平镜像）叠加 DNG `Orientation=3`（180° 旋转），合成净变换为“仅垂直翻转”，导致成片左右镜像。
- **修复**：OV7725 硬件直接配置 `COM3=0xD0`（`VFLIP=1, HMIRROR=1`），DNG 头改为 `Orientation=1`（正向）+ 实测验证的 `CFAPattern=GRBG (01 00 02 01)`。

### 3.3 顶板 `LED1 (PD9)` 常亮问题（已实机验证根除）
- **根因**：顶板原理图中 `LED1` 阳极接在 **`VCC5.0`**（非 3.3V），`PD9` 设为推挽输出高电平（3.3V）时 LED 两端仍有 `1.7V` 压差导致取景期间微亮/常亮。
- **修复**：利用 STM32F103 `PD9` 的 5V 容忍特性，在 `Core/Src/gpio.c` 将其改为 **`GPIO_MODE_OUTPUT_OD`（开漏输出）**：输出 `1`（高阻）彻底熄灭，输出 `0`（接地）点亮。状态定义：取景全灭 / 曝光与锁帧常亮 / 写 SD 卡 80 ms 闪烁 / 出错快闪 3 次。

### 3.4 MicroUSB 复用 SWD 烧录口（避坑）
- 主板 `USB1` 脚位：`Pin1=VCC3.3`、`Pin2=SWDIO`、`Pin3=SWCLK`、`Pin4=NRST`、`Pin5=GND`。
- **禁止接电脑 5V USB**（会烧毁 3.3V 域芯片）；**禁止使用 OTG MicroUSB 线**（`Pin4 ID` 与 `GND` 短接会永久拉低 `NRST`，导致 OpenOCD 报 `Halt timed out` / `DHCSR=0x02010001`）。使用普通 4 芯非 OTG 线悬空 `NRST` 配合 `reset_config none` 即可稳定烧录。

### 3.5 无 RTC 硬件与时间戳约定
- 机身电源开关 `SW4` 硬切断电池正极，`VBAT` 接 `VCC3.3`，`PC14/PC15` 悬空无 32.768 kHz 晶振，硬件无 RTC。
- FatFs 文件修改日期（`FATFS/Target/ffconf.h`）配置为 `2026-12-26`，DNG 内嵌 `DateTime` 标签（Tag `0x0132`）配置为 `"2026:08:17 00:00:00"`。

### 3.6 消除 1~2 行偶发错色（`CLKRC` 差量缓存 + `COM4=0x81` 18 MHz 裕量）
- **根因**：
  1. OV7725 的 `CLKRC (0x11)` 寄存器不经 VSYNC 阴影缓冲，在 AL422B 录帧中途重写会打乱分频相位；
  2. `COM4=0xC1`（8× PLL / `24 MHz` PCLK）紧贴 OV7725 12 MHz/路共享 ADC 上限，且 `COM2=0x03`（4× 强驱动）在未端接 FPC 排线上产生过冲振铃，导致偶发 1~2 行像素错色。
- **修复**：
  1. `ov7725_apply_always_raw_preview()` 增加寄存器差量缓存，且 `raw_preview_update_ae_awb()` 移至 `g_vsync_state = 0` 之前执行（冻结 FIFO 期间完成 SCCB 通信）；
  2. 将 `COM4` 回调至 `0x81`（6× PLL / `18 MHz` PCLK / 45 fps，较 ADC 上限留出 25% 裕量）、`COM2` 恢复柔和默认 `0x01`，保持全快门/慢门档稳跑 **15F** 且画面干净无错色。

### 3.7 SDXC（最高 2 TB / exFAT）与 `/CAYE_CAM/` 目录
- **FatFs R0.15a 升级**：替换原 CubeMX 自带的 FatFs R0.11，开启 `FF_FS_EXFAT = 1`、`FF_USE_LFN = 1`（静态 BSS 缓冲）、`FF_CODE_PAGE = 437`（紧凑 ASCII 码表，整机 Flash 仅 ~60.9 KB）、`FF_LBA64 = 0`（32-bit 扇区寻址覆盖完整 2 TB SDXC 上限）、`FF_FS_LOCK = 4`。
- **STM32F1 HAL SD 驱动修复（`stm32f1xx_hal_sd.c`）**：
  1. `ACMD41` 移除 `SD_SWITCH_1_8V_CAPACITY`（`S18R`）：STM32F103 为纯 3.3V IO 且不发 `CMD11` 降压，去除 `S18R` 后可避免严格 UHS-I SDXC 卡在初始化握手处卡死；

### 3.8 OV7725 片内 10-bit → 8-bit Gamma 压扩与 310 KB 自动还原 DNG
- **硬件实测结论（7 组对照 `GAM_G0..G6`，详细数据与脚本见 [ov7725_experiments.md](./ov7725_experiments.md)）**：
  1. `COM7 Bit 4 (Sensor RAW)` 为 DSP 旁路开关（`0x13`/`0x11` 均会旁路 Gamma）；将其清零为 **`COM7 = 0x01`**（Processed Bayer RAW）+ **`DSP_Ctrl1 = 0x87`**（仅开 FIFO、Gamma、BPC/WPC，关去马赛克/色彩矩阵/SDE）+ **`DSP_Ctrl4 = 0x02`**（RAW8），片内 `GAM1..GAM15` 在 RAW 模式下完全生效且保持 `644×480` 与 `GRBG` 排列不变。
  2. 暗场对照实测证实片内 Gamma 作用在**真 10-bit ADC 线性域**（暗部 `G0=1..16` 展开为 `1..42` 连续无空洞 42 级，精细度提升 **2.62×**，分段端点与手册公式误差 `0.00` LSB）。
- **固件共享反表架构**：
  - 512 B `s_inv_gamma_10[256]`（`uint16_t`, `0..1016`）一表三用：直接作为 DNG Tag `0xC618`（`LinearizationTable`）写入 `1,120 B` 文件头、驱动 `raw_preview_rebuild_luts()` 做 10-bit 阴影分数插值 sRGB 监看（零帧率损耗）、并在线性光域驱动 AE / Gray-World AWB。
  - **为什么文件小了一半、暗部画质反而更好**：原厂固件输出 `618 KB` 是因为把线性 8-bit RAW 每像素补 1 字节 `0x00` 塞进 16-bit 容器，多出来的一半体积全是无效零填充，实际有效精度仅线性 8-bit（丢弃了 OV7725 10-bit ADC 的低 2 bit）；本固件取消无效零填充改为 `BitsPerSample = 8`（`WhiteLevel = 1016`），单张体积降至 **`310 KB`**（写卡提速 2×），同时借助片内 10-bit Gamma 压扩与 `LinearizationTable` 把原先丢失的暗部低 2 bit 完整保留下来，使实测暗部灰阶精度达到原厂的 **2.62×**；后期如需替换自定义 Log 曲线，仅需替换 `GAM1..GAM15` 与 `s_inv_gamma_10[256]` 两张常量表。
  - **硬件 ABLC 抗温漂与分通道 12-bit 精度动态黑电平（`COM13 = 0xE6`，详见 [ov7725_experiments.md](./ov7725_experiments.md) 实验二）**：冷/热机全黑暗帧对照证实原厂关闭 `COM13=0x00` 在热机 `ISO 1600` 下暗电流飙升至 `G≈82 / R=B≈126`（+120 LSB 洋红暗雾）；开启 `COM13=0xE6` 后硬件光学暗像元在 10-bit Gamma 之前将温漂压死在 `±1.5` LSB；进一步将 `LinearizationTable` 放大至 12-bit 精度（`0..4064`、`WhiteLevel = 4064`，0 额外体积开销），按 `GRBG` 写入分通道动态黑电平（`G = 21 + 4×gain_x`，`R/B = 19 + 4.5×gain_x`，即 `ISO 100: (25,23,23,25)` .. `ISO 1600: (85,91,91,85)`），彻底消除极端拉曝光下的微弱偏绿/偏紫。

### 3.9 Type-C 充电口 `CC1`/`CC2` 共用单颗 `5.1k` 下拉（硬件避坑）
- **现象**：使用 MacBook 原装线或 100W/240W 等带 e-Marker 芯片的 USB-C 转 USB-C 快充线连接 PD 充电头时，机身无反应、无法充电。
- **根因**：主板原理图 `USB3 (TYPE-C 6P)` 将 `CC1 (A5)` 与 `CC2 (B5)` 直接短接并共用同一颗下拉电阻 `R20 (5.1k)`（与树莓派 4 初代相同的硬件缺陷）；插入带 e-Marker 的 C-to-C 线时，线内 `Ra (~1k)` 通过短接的 CC 节点被并联拉低，导致 PD 电源将其误识别为 Audio Adapter Accessory Mode 而拒绝输出 5V。
- **规避**：使用 **USB-A 转 USB-C 线** 或无 e-Marker 芯片的普通 3A C-to-C 线即可正常给板载 TP4056 充电。

### 3.10 为什么当前硬件无法实现“真断电软件关机”（电源树分析与 `AUTO SLEEP` 设计）
- **结论**：C3M1 量产主板**无法在不拨断物理电源开关 `SW4` 的前提下实现零漏电的“软件真关机”**；软件仅能实现**省电息屏休眠（`AUTO SLEEP`，省电约 85%~90%）**，适用于拍摄间隙短时待机，长时间存放仍必须拨断物理开关 `SW4`。
- **硬件电源树限制**：
  1. **无任何 MCU 可控的整机电源开关 / LDO 使能脚**：锂电池经纯机械开关 `SW4 (XKB5858)` 直连升压芯片 `U5 (MT3608L)` 的 `VIN` 与 `EN`（`EN` 经 `R21 = 47k` 焊死上拉至 `VIN`），升压至约 `6.19V (VCC5.0)` 后再分别经主板 `Q2 (AMS1117-3.3V)`、顶板 `U2 (XC6206P332MR)`、CMOS 板 `U2 (XC6206P332MR)` 与 `U5 (XC6206P282MR)` 降压供电，**MCU 没有任何 GPIO 可切断上述任一电源轨**。
  2. **Boost 拓扑自身无法仅靠 `EN` 断电**：即便改板将 `MT3608L EN` 接入 MCU，Boost 拓扑仍会经电感 `L2` 与肖特基二极管 `D1 (SS34)` 向后级直通输出 `Vbat - 0.3V`；若未来改板实现真软开关机，必须在电池与 `MT3608L VIN` 之间增加 PMOS 软开关自锁电路。
  3. **多颗外设无硬件断电/休眠脚，存在不可消除的静态底流**：
     - **`AL422B` FIFO (`U3`)**：直连 `VCC3.3`，内部 DRAM 需持续自刷新，无硬件关断脚，手册标称待机电流 `IDDS = 7 ~ 12 mA`。
     - **`AMS1117-3.3` (`Q2`)**：无 `EN` 脚，自身静态电流 `5 ~ 10 mA`。
     - **CMOS `OSC1`（12 MHz 有源晶振）**：`VDD` 与 `Tri-state` 均焊死在 `DOVDD (2.8V)` 上，持续起振耗电约 `3 ~ 8 mA`。
     - **`OV7725`**：硬件 `PWDN (C1)` 焊死接地，仅能通过 SCCB 写 `COM2[4] = 1` 进入软休眠（手册 `IDDS-SCCB ≈ 1 mA`，配合 `COM3 = 0xD0` 将 `PCLK`/数据线置高阻使 `AL422B` 退回待机）。
     - **SD 卡 (`CARD1`)**：`VDD` 直连 `VCC3.3`，空闲约 `0.2 ~ 2 mA`；另有电池分压与升压反馈电阻约 `0.3 mA`。
     - **6.19V 升压再线性降压的倍率放大**：`3.3V/2.8V` 侧剩余约 `16 ~ 32 mA` 静态电流经 `MT3608L`（`3.7V → 6.19V`，效率约 85%）折算到电池端约为 **`35 ~ 65 mA`**（典型 `~45 mA`），相比正常取景（电池端 `~350–420 mA`）可省电 85%~90%，但 `1000 mAh` 电池不关 `SW4` 仅能待机约 **15 ~ 25 小时**，不可替代物理关机。
  4. **`Standby` 待机模式不可用**：STM32F103 的 `PA0-WKUP` 原理图悬空未接（电池分压 `ADC` 接在 `PA1`），且无外部 32.768 kHz 晶振，无法用按键唤醒 `Standby` 模式；而 4 枚顶板按键均接在独立 `GPIOF` 引脚上，可通过轮询或 `EXTI` 唤醒。
- **固件 `AUTO SLEEP` 与手动休眠策略**：
  - 菜单 `AUTO SLEEP` 提供 **`5M / 10M（默认）/ 15M / 20M / 25M / OFF`** 6 档无操作自动休眠；取景时**长按 `ASA (KEYISO)` ≥ 600 ms** 也可随时手动进入休眠。
  - 进入休眠前强制将最新运行时间与配置保存至 SD 卡，随后关闭背光 `LCD_BL(0)`、ST7789 进入 `DISPOFF + SLPIN`、OV7725 进入 `COM2[4]=1` 软休眠、冻结 FIFO 与 `VSYNC` 中断、关闭 `ADC1`、系统时钟切至 **8 MHz HSI（关 HSE 与 PLL）**，在 `TIM6` `250 µs` 节拍间执行 ARM `__WFI()` 睡眠，并以 **100 Hz PWM + Gamma 2.0 曲线（3.0s 周期）** 驱动开漏 `LED1 (PD9)` 做平滑呼吸灯提示（此时可直接拨断物理开关 `SW4` 安全关机并保留准确关机时间）。
  - **短按 `ASA` (`KEYISO`) 立即唤醒 / 按其余顶键速览最轻载电量**：先确认长按进休眠后的按键已松开 ≥ 30 ms，再响应下一次 30 ms 消抖短按；唤醒后恢复 72 MHz PLL、传感器与屏幕，将休眠期间持续走时的最新时间戳回写 SD 卡，等待首帧稳定画面绘入显存后再点亮背光（零闪烁），并自动吞掉唤醒时的该次 `ASA` 按键防止误切 ISO。普通休眠期间若按下非唤醒键（`SHOT` / `4X` / 过片扳手），会在保持 OV7725 休眠且点亮背光之前采样最轻载电压，于黑屏右下角按 HUD 电池样式与配色同时显示电压和百分比（`x.xxV xxx%`）`3 s` 后自动回睡（期间按 `ASA` 可立即唤醒，软时钟同步补齐耗时不丢时）。
- **为什么禁止在休眠 / 开机状态（`SW4` 闭合）下长时间充电（锂电安全分析）**：
  - 主板 `U6 (TP4056-MS)` 无 Power-Path（PMOS + 肖特基）负载分离电路，`Pin 5 (BAT)` 直接与锂电池和 `SW4 → MT3608L` 并联；`Pin 1 (TEMP)` 直接接地（无 NTC 温度保护）；`Pin 2 (PROG)` 经串联的 `R13 (1k) + R14 (1k) = 2.0 kΩ` 接地，对应恒流充电电流 $`I_{\text{CHG}} = 1200 / 2000 \approx 600\text{ mA}`$、恒压截止电流 $`I_{\text{TERM}} = 0.1 \times I_{\text{CHG}} \approx \mathbf{60\text{ mA}}`$。
  - 当 `SW4` 闭合处于休眠状态时，后级静态负载折算到 `4.2 V` 电池端仍有 **`~45–65 mA`**（开机取景更高达 `~300+ mA`），与 `60 mA` 截止阈值相当甚至超出：
    1. 若休眠负载 $`\ge 60\text{ mA}`$，`BAT` 端总电流永远不会跌破 `60 mA`，**TP4056 永不截止**，锂电将被长期钳位在 `4.20 V` 持续浮充（加速析锂、容量衰减与鼓包风险）；
    2. 即使休眠负载略低于 `60 mA`（如 `~45 mA`），不仅恒压阶段拖尾过充，截止后电池也会立即被休眠负载拉回 `4.05 V` 再充阈值，在密闭塑料外壳内形成无休止的 `4.05V ↔ 4.20V` 微循环充放与 `TP4056/MT3608L` 持续发热。
  - **实测补充与推荐操作**：本机实测在自动休眠与亏电休眠状态下外接充电均可正常跳绿灯自动停充（说明该样机在 `4.2V` 端休眠底流实际低于 `TP4056` 截止电流），但因两值余量较窄且不同批次/个体器件存在公差，仍不排除个别机身无法截止或微循环浮充的风险；日常长时间充电仍建议先长按 `ASA` 休眠落盘时间，再**拨断物理开关 `SW4`** 充电（此时后级负载为 `0 mA`，最稳妥）。
- **四档低电保护、`<3.20V` 低电强制休眠与工作/休眠双曲线电量标定**：
  - **带载与休眠轻载双曲线标定（`Core/Src/adc.c`，完整 24 组实测数据见 [ov7725_experiments.md 实验五](./ov7725_experiments.md)）**：主板电池分压网络（`HC-1.25-2PWT Pin 2 → R17 10k → PA1 → R18 10k || C16 100nF → GND`）经稳定工作→立即休眠全段实测，呈现典型单节锂电 **U 型内阻特征**——高电端（`≥ 3.91V` 工作态，含 `3.91/3.94V` 切低功耗即回升 `+20 mV`）与低电端（`≤ 3.45V`）工作/休眠压差为 **`+50 mV`**，而中段放电平台（`3.50–3.84V`）压差稳定收窄至 **`+30 mV`**。扣除刚拔电表面虚电（绿灯停充 `4.05/4.09V`）后以工作 `4.00V` / 休眠 `4.05V` 为 `100%`、以禁写 SD 临界工作 `3.25V` / 休眠 `3.30V` 为 `0%`：工作态 `adc_mv_to_percent()` 采用 `3250 / 3380 / 3490 / 3550 / 3590 / 3630 / 3680 / 3740 / 3820 / 3910 / 4000 mV`，休眠轻载 `adc_mv_to_percent_light()` 采用分段标定表 `3300 / 3430 / 3530 / 3580 / 3620 / 3660 / 3710 / 3770 / 3850 / 3960 / 4050 mV`（全段误差 `≤ ±1%`、中位误差 `0%`），并按百分比同步黄/红警示色（`≤25%` 黄、`≤16%` 红），消除工作与休眠间的百分比及颜色跳变。
  - **四档电压阈值（仅真实电池 `≥ 2.00V` 生效，避免纯 ST-Link 供电误触发）**：
    - `< 3.52V`：底栏电量变黄预警（`~25%`）；
    - `< 3.45V`：底栏电量变红警告（`~16%`）；
    - `< 3.25V`：锁定全部 SD 卡写入（禁止拍照存卡、回看删片、格式化与写配置），菜单保存受阻时底栏明确显示红色 **`LOW BAT`** 而非 `SD ERR`；
    - `< 3.20V`（`camera_enter_low_bat_sleep()`）：在**开机 LCD 初始化后（跳过开机动画与 SD 挂载）、取景运行连续 2 次 2 s 采样、普通休眠 `ASA` 唤醒复检**三处统一触发——先弹出 **15 s** 红色提示框明确说明正在休眠而非断电（`LOW BATTERY! / x.xxV - SLEEPING (NOT OFF) / SWITCH OFF TO CHARGE / LED BLINK = POWER STILL ON`），随后进入 **8 MHz HSI + `TIM6` 60 Hz 节拍（`PSC=3, ARR=33332`，误差 `+10 ppm`）** 的 SWD 安全 `__WFI()` 低功耗休眠：
      1. 息屏期间以 `LED1` 每 3.00 s 短双闪（`66.7ms ON / 116.7ms OFF / 66.7ms ON`，占空比 ~4.4%）区别于普通呼吸灯，同时每 60 拍精准调用 `c3m1_clock_advance_sec(1)` **保持软件时钟持续走时**（期间不检测 SD 热插拔，交由切入普通休眠后再监测）；
      2. 每 3.00 s 在灯灭间隙调用 `adc_battery_sample_hsi8_mv()`（`ADCCLK = 8 MHz / 2 = 4 MHz`，单次仅耗时 `~1.1 ms`、`0.037%` 占空比，不启 HSE/PLL、不依赖 SysTick、采完即关 ADC1）超低功耗巡检轻载电量；一旦检测到轻载电量恢复至 **`≥ 25%`**（约 `3.56V`，对齐低电插电重启实测 `3.53/3.57V`）并连续 2 次（6 s）确认，即保持息屏 8 MHz HSI 状态**零闪烁无缝交接回普通呼吸灯休眠**（恢复 `ASA` 唤醒与 3 s 电量速览，零递归调用栈，支持开机态与运行态全部 3 个入口）；
      3. 电量未恢复前按任意顶键仅复显 **5 s** 实时电压告警（全程保留走时）后继续回睡；若按键采样时电量已达 `≥ 25%` 则直接切入普通休眠。

### 3.11 机内 12-bit / 14-bit / 16-bit HDR 包围合成与 OV7725 时序要点
- **恒定 ISO、纯快门包围策略（不强限 ISO）**：
  - `HDR MERGE`（`12B 2F`：`-1/+1 EV`，`14B 3F`：`-2/0/+2 EV`，`16B 4F`：`-3/-1/+1/+3 EV`，相邻帧恒定 2.0 EV / 4× 重叠，最高 64× 动态范围跨度填满 16-bit `WhiteLevel ≈ 64,576`）在整组拍摄中**锁定同一 `GAIN` 寄存器（ISO 不变）**，仅通过 `AEC / AECH` 与 `DM_LN / CLKRC` 调节积分行数实现曝光步进。
  - 因此即便 EV 0 已经处于 `ISO 3200`（`GAIN=0xFF`），`+1 EV` / `+2 EV` 长帧依然靠延长快门完成，**不存在“超过 ISO 3200 无法处理”的增益溢位问题**；唯一硬边界为快门极限（最短 `1` 行 = `1/23000s`，最长 `45,918` 行 = `2.0s`），触及时固件自动平移钳位，确保各分帧曝光严格递增无重复。
  - 固件刻意**不对 HDR 模式强加 ISO 上限**，以保持“除按下快门后执行流程不同外，其余操控与测光语义与普通拍照完全一致”。不过，OV7725 在 `ISO 1600/3200` 下模拟增益本身会抬高暗电流黑电平并压缩约 3–4 EV 有效动态范围，且 `AUTO 快门 + AUTO ISO` 的 P 曲线默认按手持防抖设计（暗场优先在 `1/50s` 上拉高 ISO）；因此**三脚架 HDR 拍摄时建议手动切至 `ISO 100` 或 `ISO 200`**，用更长快门换取最佳信噪比与色彩纯度。
- **已验证并根除的两项 OV7725 硬件时序陷阱**：
  1. **向上增大 `AEC` 时的 510 行整帧过渡 Bug**：当 `DM_LN == 0` 且新 `AEC > 旧 AEC` 时，OV7725 在 `VSYNC_A` 锁存后首帧的卷帘复位比较器会错过 `510 - AEC`，导致整帧 480 行积分满 510 行（高速快门下最高过曝 42×）。固件在 `ov7725_apply_exact_lines()` 中跳过未变化的 `CLKRC/COM8/COM5/DM_LN/GAIN` 写入，并在 `hdr_capture_frame_to_fifo()` 对所有 `<= 4592` 行（`<= 200 ms`，常规快门仅多 `+22 ms`）追加 1 帧稳定期 `VSYNC_C`，彻底根除该问题。
  2. **`DM_LN` 哑行插在 `HREF` 之前导致的提前锁存截断**：当长帧需要插入超过 ~1,000 行 `DM_LN`（`> 45 ms`）时，固定 `45 ms / 80 ms` 超时会在有效行 Row 0 到达前就拉低 `OV7725_WEN`，使 AL422B 残留上一帧旧数据。现统一改为完整等待下一次 VSYNC 中断（`g_vsync_state == 2`）由硬件同步锁存全部 `DM_LN` 哑行与 480 有效行，并辅以大于整帧周期的安全看门狗。
- **零额外 `.bss` 流式融合与保色相高光映射**：
  - 同组文件以首帧编号命名（`CDIxxxxx_0/_1[/_2[/_3]].dng` 与 `CDIxxxxx_hdr.dng`），`ShutterCount` 按实际曝光帧数累计（`2F` +2、`3F` +3、`4F` +4），最后一帧保留在 AL422B FIFO 中免重读；融合采用 `2×2` GRBG 色块同步权重（防止高光交接区三通道错位切帧产生色带）、受控 `[0.65×..1.55×]` 实测行比微调、白点锚定保色相 Reinhard 压肩（`c3m1_color_hdr_to_srgb8`）以及 `4,096 B` 扇区对齐写卡输出 `CDIxxxxx_hdr.dng`。
  - **实拍动态范围验证（`ISO 100`，详见 [ov7725_experiments.md](./ov7725_experiments.md) 实验三）**：在 `1/100s` 同场景实拍中，有效动态范围从单帧 10-bit 的 **`9.32 EV`** 逐级提升至 `12B 2F` **`11.16~11.47 EV`**、`14B 3F` **`12.69~13.15 EV`**、`16B 4F` **`14.13~14.60 EV`**（`16B 4F` 较 `14B 3F` 实测再增 **`+1.21~+1.45 EV`**，高光实得 `+0.96 EV` 可将 `1/50s` 压测下 `0.88%` 过曝灯条拉回至 `0.00%`，暗部在散粒噪声区再增 `+2.2~+3.6 dB`）。

### 3.12 JSR 超分连拍模式（`JSR BURST` + 匹配黑场 + 满阱容量参考）
为方便三脚架拍摄多帧同曝光 RAW 序列并直接导入 **Jiangtherapee-Super-Resolution-World-Best（JSR）** 进行多帧超分重建与降噪，固件新增纯运行态挥发选项 `JSR BURST`（`OFF / 7F / 14F / 30F`，位于菜单 `HDR MERGE` 正下方，不写入 `c3m1.cfg`，开机复位 `OFF`，零新增 `.bss` RAM）：
- **与 `HDR MERGE` 正交组合 & 快门计数规则**：
  - `JSR BURST` + `HDR = OFF`：锁定首帧曝光行、增益与白平衡，连续零 SCCB 抖动采集 `7 / 14 / 30` 张 10-bit 线性化 DNG（左上角显示 `JSR7 / JSR14 / JSR30`），每张实际曝光快门计数 `+1`（连同黑场共 `N + 1` 次）。
  - `JSR BURST` + `HDR = 12B 2F / 14B 3F / 16B 4F`：连续拍摄 `7 / 14 / 30` 张机内流式合成的 12/14/16-bit 线性 HDR DNG（左上角显示 `H12x7 / H14x14 / H16x30`）；**首帧标定并锁定整组 `ratio_q8`、`WhiteLevel`、`BaselineExposure`**，后续全部亮帧与黑场完全复用同一套标定系数以消除帧间亮度微抖；快门计数与独立 HDR 一致，按实际物理曝光次数累计（每组 HDR `+nf`，连同黑场共 `(N + 1) × nf` 次）。
- **目录与文件命名、黑场提示及后置删单帧开关（`DEL HDR BRK`）**：
  - 子目录以本次连拍第一张照片编号加张数后缀命名：`0:CAYE_CAM/YYYYMMDD/CDIxxxxx_7`（或 `_14` / `_30`）；`playback.c` 自动识别此类 JSR 子目录并将整组折叠为 1 条回看条目，默认选取首张代表亮帧（`CDIxxxxx.dng` 或 `CDIxxxxx_hdr.dng`）渲染 1X / CLIP / INFO / 1:1 放大，在底栏与 `INFO` 页以品红色标注具体拍摄类型（`JSR 7F/14F/30F` 或 `J7/J14/J30 H12/H14/H16`），`INFO` 页汇总目录内实际亮帧数、黑场完整性及整组体积，删除时二次确认整组清理目录。
  - 目录内文件命名与普通 / HDR 模式完全一致：10-bit 模式亮帧为 `CDIxxxxx.dng`，黑场为 `CDIyyyyy_dark.dng`；HDR 模式亮帧为 `CDIxxxxx_0.._(nf-1).dng` + `CDIxxxxx_hdr.dng`，黑场为 `CDIyyyyy_0.._(nf-1).dng` + `CDIyyyyy_dark.dng`。
  - 拍摄流程：按快门 → 3 秒脚架自拍倒计时（`JSR DELAY 3s..1s`，可按 `ASA/4X/扳手` 取消）→ 连续拍完 `N` 张亮帧（中途帧间按 `ASA` 可安全中止并保留已存帧）→ 弹出全屏醒目提示 **`JSR DARK FRAME / COVER LENS COMPLETELY`**，提醒用户**完全遮挡镜头**后按 `SHOT` 拍摄最后一张黑场 `CDIyyyyy_dark.dng`（也可按 `ASA` 跳过）→ 若菜单 `DEL HDR BRK`（位于 `PB SKIP BRK` 下方，`c3m1.cfg` schema v12，默认 `OFF`）开启，则在**全部亮帧与黑场拍完并合成完毕后**统一删除所有 `_0.._(nf-1)` 包围单帧（独立 `HDR MERGE` 模式亦同步受此开关控制），最后恢复取景并一次写 Flash 更新 `ShutterCount`。
- **JSR 满阱容量（Full Well Capacity, 电子数 $`e^-`$）参数换算与参考表**：
  - **传感器基准**：OmniVision OV7725（`6.0 µm` 像素）数据手册标称阱容 `17,000–26,000 e⁻`；基于 C3M1 实机 `ISO 100` 平滑块光子转移斜率（PTC）实测估算 $`K_{12} \approx 4.5\ e^-/\text{ADU}_{12}`$，有效基准满阱容量 $`\text{FWC}_{\text{ISO 100}} \approx \mathbf{18,000\ e^-}`$（`17,000–20,000 e⁻`）。
  - **随 ISO 变化规律**：模拟增益 $`g = \text{ISO} / 100`$ 使单电子对应的数字输出放大 $`g`$ 倍，ADC 在 $`1/g`$ 物理电子数处提前饱和，故单帧等效满阱容量按增益反比下降：
    $$\text{FWC}_{\text{single}}(\text{ISO}) = \frac{\text{FWC}_{\text{ISO 100}}}{\text{ISO} / 100}$$
  - **随多帧 HDR 合成变化规律**：机内 HDR 合成保留最长曝光帧在暗部/中灰段的线性刻度（1 ADU 对应同 ISO 单帧的同一光子数），并将 `WhiteLevel` 拓展 $`M`$ 倍（实测 `12B 2F`: $`M \approx 4.1\times`$；`14B 3F`: $`M \approx 16.8\times`$；`16B 4F`: $`M \approx 65\times`$）。在 JSR 归一化至 `[0, 1]` 的泊松散粒噪声模型 $`\mathrm{Var}(x) = x / \mathrm{FWC}_{\text{eff}}`$ 下：
    - **暗部/中灰主导等效值（首选）**：$`\text{FWC}_{\text{HDR}} = M \times \text{FWC}_{\text{single}}(\text{ISO})`$；
    - **亮部/高光接管段注意**：当像素超过最长帧饱和点、改由短曝光帧乘以倍率 $`r`$ 接管时，局部散粒噪声方差会随 $`r`$ 放大，局部有效满阱逐级回落趋近 $`\text{FWC}_{\text{single}}(\text{ISO})`$；若大面积高光场景下觉得 JSR 亮部降噪偏弱或微噪，可将填入的满阱容量适当下调至表中 HDR 值的 `1/2 ~ 1/4`。
  - **重要提醒**：`7F / 14F / 30F` 连拍张数**不会**改变单张 DNG 的满阱容量！JSR 填入的是**单张输入 DNG** 对应的有效满阱电子数，软件内部会自动按输入帧数累计总光子统计，**切勿再乘以 7 / 14 / 30**。

| ISO（增益） | 单帧 `10-bit` DNG | `12B 2F` HDR（$`M \approx 4.1\times`$） | `14B 3F` HDR（$`M \approx 16.8\times`$） | `16B 4F` HDR（$`M \approx 65\times`$） |
| :--- | :---: | :---: | :---: | :---: |
| **`ISO 100` (`1×`)** | **`18,000 e⁻`** | `~74,000 e⁻` | `~302,000 e⁻` | `~1,170,000 e⁻` |

## 4. 纯英文菜单系统与 SD 卡二进制配置（`CAYE_CFG/c3m1.cfg`）

### 4.1 为什么将配置固化在 SD 卡而非内部 Flash？以及快门计数页磨损均衡
- 避免频繁切换 ISO / 调整菜单反复擦写 STM32F103 单 Bank 内部 Flash（页擦除会阻塞中断 20~40 ms 且存在擦写寿命限制），内部 Flash 仅保留位于最后 64 KB 保留区起点的 `0x08070000` 快门计数页（链接脚本 `STM32F103ZETX_FLASH.ld` 硬锁固件上限 `448 KB = 0x08000000..0x0806FFFF` 防止越界覆写）。
- **快门计数页自动识别与 1,022 槽磨损均衡（`Drivers/BSP/STMFLASH/stmflash.{h,c}`）**：
  - 单页 `2 KB`（1,024 半字）支持 **`STOCK`**（原厂单槽：`slot[0]` 存计数值、`slot[1..1023] = 0xFFFF`）与 **`WEAR-LVL`**（`slot[0..1021]` 顺序追加写 + 页尾 `slot[1022..1023] = 0x574C / 0x4333` `"C3WL"` 魔数，写满 1,022 次才擦 1 次页，寿命 > 1,000 万次）两种格式；开机与写盘自动通过页尾魔数判别，并通过菜单 `FORMAT SD` 下方的 **`COUNTER FMT`** 开关热切换（低电 `<3.25V` 拦截）。
  - **`STOCK → WEAR-LVL` 零擦除原地升级**：检测到 `slot[1..1023]` 全 `0xFFFF` 时直接补写页尾 `"C3WL"` 魔数（0 擦除、无断电窗口）；**`WEAR-LVL → STOCK` 降级**：擦页后仅写 `slot[0] = 最新计数`，与原厂格式 100% 字节一致。
  - **翻页防掉电顺序与 2 KB `.bss` 回收**：满槽擦除后严格先写 `slot[0]`、最后写 `magic_lo / magic_hi`（写魔数前掉电仍可按 `STOCK` 无损读回 `slot[0]`）；全路径校验 `HAL_FLASH_*` 返回值并立即回读比对，保留 `0xFFFF` 作空槽哨兵（`shutter_count_add()` 将有效计数回绕至 `1..65534`）；彻底移除原厂 `g_flashbuf[1024]`，永久回收 **`2,048 B` `.bss`**。
- 无 SD 卡时禁止进入菜单（直接弹窗 `NO SD CARD!`），确保所有配置变更均可即时落盘且语义一致；若在菜单打开期间热拔 SD 卡，菜单会立即检测到 `SDOK` 变化并安全退出、卸载文件系统。

### 4.2 48 字节二进制配置文件格式（schema v19）与无损迁移
配置结构 `c3m1_cfg_t`（`Core/Inc/c3m1_cfg.h`，`_Static_assert(sizeof == 48)`）保存在 `0:CAYE_CFG/c3m1.cfg`：
- 头部校验字段：`magic (0x314D3343 = "C3M1")`、`schema_ver (19)`、`struct_size (48)`、`fw_major / fw_minor / fw_patch`（由 `Makefile` 自动从最新 Git tag 解析注入 `build/fw_version.h`，仅作记录不再因小版本升级而重置用户配置）。
- 业务设置字段：覆盖 `iso_idx`、`max_auto_iso`、`min_auto_sht`、`flicker_mode`、`bat_disp`、`film_lever`、`hist_en`、`peak_color`、`grid_en`、`save_mode`、`wb_mode`、`debug_info`、`ev_comp`、`meter_mode`、`auto_sleep`、`boot_clock`、`saved_epoch`、`pb_skip_brk`、`del_hdr_brk`、`lens_focal_mm`、`lens_fnum_x10`、`lens_distort`、`lens_vignette`、`lens_dist_incam`、`lens_profile`、`high_iso_nr`（v18）、`anti_alias`（v18）与 `color_mode`（v19，复用原 `reserved[1]` 保持 48 B 定长）。
- 尾部校验字段：IEEE 802.3 `crc32`（覆盖前 44 字节）。
- **加载与无损迁移策略**：开机及热插卡挂载时依次验证 `文件大小`（48 B，或兼容旧版 40 B v10–v14 / 44 B v15–v16）→ `magic/schema/struct_size` → `crc32` → 各字段枚举范围；遇到 v10–v18 旧配置时自动补全新增字段默认值并原地重签落盘，实现跨版本升级零配置丢失。
- **短按 ISO 防抖落盘**：取景时短按 `KEYISO` 切换 ISO 仅设置 `1200 ms` 延迟保存定时器（并在拍照或进菜单前强制立即刷盘），避免连按 ISO 时反复触发 SD 卡写操作。

### 4.3 菜单交互、机内格式化与版本哈希注入
- **按键解耦**：`KEY4X (PF3)` 采用“松手触发短按（切换 1X/4X 放大）、按住 ≥ 600 ms 触发长按（进入菜单）”；`KEYISO (PF1)` 采用“松手触发短按（切换 ISO / 菜单返回 / 休眠唤醒）、按住 ≥ 600 ms 触发长按（手动休眠并保存时间）”；退出菜单时等待顶板按键全部释放再调用 `key_init_state()`，防止按 `SHOT` 选 `EXIT MENU` 后误触发快门。
- **可配置 4 段 P 曲线**：菜单中的 `MAX AUTO ISO`、`MIN AUTO SHT`、`ANTI-FLICKER` 直接驱动软件 AE 闭环（`50HZ` 折点 `1/100↔1/50`，`60HZ` 折点 `1/120↔1/60`，`OFF` 直连）；当 `MIN AUTO SHT` 允许慢于 `1/50s`（如 `1/25 / 1/15 / 1/8`）且暗光下 ISO 已顶至上限后，P 曲线进入第 4 段继续放慢快门（预览仍保 45 fps / 15F，拍照自动走慢门单帧原子曝光路径）。
- **零额外 RAM 机内格式化（`FORMAT SD`）**：开启 `FF_USE_MKFS = 1` 并修复 `sd_diskio.c` 中 `GET_BLOCK_SIZE` 返回值（`1` 扇区而非旧版 `512` 字节）；`f_mkfs()` 复用 DNG 写盘静态缓冲 `s_sd_io_buf[4096]`（零额外 SRAM 开销），使用 `FM_ANY` 自动按卡容量格式化为 FAT32（≤32 GB）或 exFAT（≥64 GB），格式化前检查 `>= 3.25V` 与二次确认，完成后自动重挂并重建 `CAYE_CAM` 与 `CAYE_CFG/c3m1.cfg`。
- **构建期自动版本与短哈希**：`Makefile` 在编译前自动生成 `build/fw_version.h`（带 `cmp -s` 变更检测避免无意义全量重编），定义 `FW_VERSION_STR` 与 `FW_GIT_HASH_STR`（工作区有改动时自动追加 `-dirty`），显示于开机动画、菜单底栏及 `SYSTEM INFO` 页面。

### 4.4 零闪烁取景叠加层（迷你直方图、常驻峰值对焦、三分构图线）
三项取景辅助全部在 `ov7725_camera_refresh()` 的 DMA 行缓冲（`s_line_buf`）内联合成，**单次 DMA 发送完成、零闪烁、总静态开销仅 512 B SRAM**：
- **64 档实时迷你直方图（`HISTOGRAM` 菜单可开关）**：在 `1/4` 抽样行叠加统计之前（峰值对焦修改像素之前）按 `0.25R + 0.5G + 0.25B` 归入 64 档 sRGB 亮度桶（`128 B`），帧末归一化为 `0..22 px` 柱高（`64 B`）；下一帧在 `y = 192..217`（严格对齐 1X 双行偶奇边界）右下角直接内联渲染 `66×26 px` 暗底直方图与 1/4 刻度线，高光截断 >2% 时右侧边框与高光柱亮红警示。
- **常驻 2D 峰值对焦（`PEAK COLOR` 菜单选 `RED / YELLOW / WHITE / BLUE`）**：提取解马赛克后 `G6` 通道（`0..63` sRGB 感知均匀空间），采用水平 1px NMS 细丝与双行乒乓 `s_peak_g[2][320]` + `s_lut_g6[256]` 零拷贝单遍扫描，随当前模拟增益自适应抬高阈值，在 `1X` 与 `4X` 放大下均精准勾勒合焦轮廓。
- **半透明三分构图线（`GRID 3X3` 菜单可开关）**：在 `1X` 构图模式下于 `x = 106, 213` 与 `y = 79, 159` 处以 2 条整数指令执行 50% 半透明提亮混合，1px 精细不遮挡主体；两条竖线贯通至屏幕最底端 `y = 239` 且先绘制于底栏之下，使其在底栏区被 50% 半透明暗底自然压暗；`4X` 放大对焦时自动隐藏。
- **无顶线 50% 半透明底栏（取景与全屏回看统一视觉）**：取景底栏（`vf_overlay_osd_row()`）与全屏回看 1X（`CLEAN`/`CLIP`）/ 4X `ZOOM`（`playback.c` 全路径含 18-bit RGB666 与 RGB565）均覆盖完整 `320×240` 画面并在 `y = 220..239` 内联叠加 **50% 半透明暗底**（无顶部分割横线；1X 抗锯齿同步覆盖底栏 20 px 消除 `y = 220` 交界断层）；回看通过 `c3m1_pb_ctx_t.bar_buf` 复用空闲的 `s_osd_bar_buf[12][160]`（0 B `.bss` 增长，最深调用链含中断 `~5,360 B < 6,144 B` `_Min_Stack_Size`），退出回看立即重建取景底栏。

### 4.5 DNG 嵌入预览图（`IFD0` + `SubIFD`）、`OpcodeList3` 镜头矫正与流式 VGA JPEG 直出
- **多 IFD DNG 1.4 布局（`Core/Src/c3m1_dng.c`）**：程序化生成 `2,048 B` 文件头，`IFD0` 承载 `160×120×3` 未压缩校准色彩（或黑白模式下对应影调）RGB 预览图（`57,600 B`，偏移 `0x800`；`ANTI-ALIASING = ON` 时采用 `4×4` 全区域线性光盒式下采样），通过 `SubIFDs (0x014A)` 指向承载完整 `644×480` 10-bit Gamma 压扩 GRBG RAW 的 `SubIFD`（`309,120 B`，含 `LinearizationTable`、动态分通道 `BlackLevel`、`ColorMatrix1`、`ActiveArea`、`NoiseProfile`）。拍照锁帧后分两遍借助 AL422B `/RRST` 读指针复位流式写出，兼顾桌面/手机系统原生缩略图与机内秒开回看。
- **镜头预设列表（`LENS PROFILE`）、EXIF 元数据（`LENS FOCAL` / `LENS APERTURE`）、DNG 1.4 `OpcodeList3 (0xC74E)` 与全链路机内矫正（标定见 [ov7725_experiments.md 实验 6 / 实验 7](./ov7725_experiments.md)）**：菜单 `MIN AUTO SHT` 下方、`LENS FOCAL` 正上方提供持久化镜头列表 `LENS PROFILE`（默认 `0 = UNKNOWN`；已知原装等效 ~50mm 镜头为 `1 = 6mm F1.6`）：选择已知镜头时自动填充下方 `LENS FOCAL = 6mm`、`LENS APERTURE = F1.6`、`LENS DIST = -0.072`、`LENS VIG = +1.15`（之后仍允许单独自定义微调），并在 DNG（常规与 HDR）与直出 JPEG 的 `ExifIFD` 写入标准 `LensModel (0xA434)`（`"C3M1 6mm F1.6"`）；选择 `UNKNOWN` 时保持当前四项配置不变，且 EXIF `LensModel` 留空（不写入）；下方依次提供 `LENS FOCAL`（`lens_focal_mm ∈ {0, 4..500}`，结构体直接存镜头原始标称毫米值，非零时同步写入标准 EXIF `FocalLength (0x920A)` 及按 `9×` 换算的 `FocalLengthIn35mmFilm (0xA405)`）、`LENS APERTURE`（`lens_fnum_x10 ∈ [0, 320]`，步进 `0.1`、范围 `F0..F32.0`，同步写入 `FNumber (0x829D)`）、`LENS DIST`（`-0.200..+0.200`，步进 `0.002`）、`LENS VIG`（`0..+2.50`，步进 `0.05`）与 `INCAM DISTORT`（默认 `OFF`）。`LENS DIST` 与 `LENS VIG` 均为 `0` 时不写 Tag `0xC74E`；任意一项非零时在 SubIFD 写入大端序标准 `OpcodeList3`（先在原始镜头坐标执行 `FixVignetteRadial` ID=3：$`g(r) = 1 + k_0 r^2`$，再执行单平面 `WarpRectilinear` ID=1：$`r_{\text{src}} = r(k_{r0} + k_{r1} r^2)`$，采用 4:3 最大内接无黑边缩放 $`k_{r0} = 1 - 0.36 k_{r1}`$（桶形）或 $`1 - k_{r1}`$（枕形），光学中心 `(0.5, 0.5)`，归一化半径 $`m = \sqrt{320^2 + 240^2} = 400\text{ px}`$，JSR 黑场自动跳过）：
  1. **直出 VGA JPEG（`c3m1_jpeg.c`）**：开启 `INCAM DISTORT` 时走 50 行滚动 Bayer 环形缓冲 + MCU 四角分段双线性步进 + 单遍 12 次查表 Bayer 通道/菱形绿晶格双线性（零 `% 50` 除法，先在源镜头坐标做 12-bit 线性暗角补偿再重采样）；关闭时走 `20` 行（彩色）或 `12` 行（黑白）滑动条带 + Malvar-He-Cutler 5×5 梯度修正解马赛克快路径；
  2. **DNG / HDR 嵌入 `160×120` 缩略图（`main.c`）**：复用 16 行 RGB888 环形缓冲做双线性 `WarpRectilinear` + 线性暗角补偿与 `4×4` 盒式抗锯齿，使机内 1X 回看与桌面相册缩略图严格对齐 Lightroom；
  3. **1X 实时取景监看（`main.c`）**：采用 **64 级融合暗角**（将 Padé 近似 $`g^{1/2.2}`$ 的 Q8 增益表 `s_vf_vig_lut[65]` 按 16 像素段代数融合进 `vf_chroma_vig_pack_rgb565` 的单周期 `MUL` + `USAT ASR` 指令与黑白 S 曲线前缩放，彻底移除第二遍 RGB565 后处理与 `1,568 B` 暗角查表 `.bss`），配合 11 节点水平对称 0 栈溢出 `vf_warp_row_1x()` 与 U1 行间 50/50 SWAR 混色（`vf_avg_row_be()` `LDRD/STRD`），实机验证 **`INCAM DISTORT (ON/OFF) × ANTI-ALIASING (ON/OFF)` 全部 4 种组合在 `LENS VIG = +1.15` 下均稳跑 `9–10 fps`**，`4X` 原生 1:1 放大（$`r \le 0.5`$ 畸变 `< 1.4 px`，始终不重采样以保对焦锐度）稳跑 **`8 fps`**。
- **纯整数流式 VGA JPEG 编码器（`Core/Src/c3m1_jpeg.c`）**：彩色路径采用 `50×644 B`（`32.2 KB`，分时共享）滑动 Bayer 缓冲完成 Malvar 5×5 或双线性去马赛克 → 12-bit 线性化扣黑 → 线性暗角与可选畸变矫正 → Gray-World AWB → 55% 混合 Camera→sRGB CCM → IEC sRGB OETF → BT.601 YCbCr 4:2:0 → ISO 自适应三级降噪 → 纯整数 IJG Loeffler 8×8 DCT + 自然序 Q16 倒数 Q90 量化（零除法）+ 标准霍夫曼编码（零浮点、零堆分配）；黑白路径经 `noinline` 兄弟函数 `jpeg_encode_bayer_vga_gray`（栈帧仅 `1,248 B`）跳过彩色 CCM 直接编码单通道灰度 Baseline JPEG（`SOF0 Nf=1, 1×1 8×8 MCU`）。

### 4.6 统一抗锯齿、三级高感降噪与全链路黑白胶片模式
- **统一抗锯齿管线（`ANTI-ALIASING`，schema v18 默认 `ON`，0 新增 `.bss`）**：
  - **1X 监看 + 快门定格预览 U1 抗锯齿**：在 `INCAM DISTORT = OFF / ON` 两条路径上用 Thumb-2 `LDRD/STRD` 8 像素展开执行行间 50/50 混色（`y1 = avg(cur_clean, next_clean)`），借 `scratch` 尾部存放双清洁行与第 3 槽 `peak_g[2]` 实现 `y0` 原地零 `memcpy` DMA，峰值对焦仅叠于 `y0` 保持 1 px 锐线；
  - **成片抗锯齿**：DNG `160×120` 缩略图采用 `4×4` 全区域线性光盒式下采样消除回看锯齿与摩尔纹；直出 VGA JPEG 常规路径采用 Malvar-He-Cutler 5×5 梯度修正解马赛克消除斜线拉链锯齿与红蓝彩边。
- **ISO 自适应三级高感降噪（`HIGH ISO NR`，schema v18 默认 `ON`，0 新增 `.bss`、0 软浮点）**：
  - **直出 JPEG（`c3m1_jpeg.c`）**：`ISO ≤ 200` 或关闭时 100% 旁路；`ISO 250–320` 轻度色度联合双边；`ISO 400–640` 保留 Malvar 5×5 并叠加 8-bit Gamma 域热/冷像素剔除 + 查表色度/暗部增强亮度双边 + 融合 DCT AC 柔缩；`ISO 800–3200` 切换平滑 3×3 双线性并随 ISO 渐进增强（兼容畸变开/关）；
  - **DNG 1X / 4X 机内回看（`playback.c`）**：按单文件 EXIF `ISO` 与 `HIGH ISO NR` 开关驱动（绝不修改磁盘 DNG），复用共享 `scratch` 尾部实现 1X 缩略图 3×3 联合双边与 4X 放大（畸变/非畸变、8-bit/16-bit HDR）热像素剔除 + 5-tap 色度联合双边 + 3-tap 暗部增强亮度双边，配内联 `cam12→sRGB8` 与单周期 `__USAT`/`__SSAT` 融合 RGB666 抖动输出。
- **全链路黑白胶片模式（`COLOR MODE`，schema v19 默认 `COLOR`，0 新增 `.bss`）**：
  - **色彩科学**：跳过 OV7725 彩色 CCM（避免负权重矩阵带来约 `1.55×` 噪声放大），在线性光域以正权重混色（`B&W` / `B&W HI`：`(64R + 174G + 18B + 128) >> 8`；`B&W RED` `#25A`：`(168R + 80G + 8B + 128) >> 8`），再经 Flash `.rodata` 三张 256 级单调 S 曲线查表输出影调；
  - **四链路贯通**：取景器采用 64 级严格中性 RGB565 查表（`R5 == G6/2 == B5` 零偏绿、保留彩色峰值与后台 AWB/AE，左上角叠加 `BW/BW+/BWR`）；直出 JPEG 编码真单通道灰度 Baseline JPEG（`SOF0 Nf=1`，S 曲线前执行保颗粒柔和亮度 NR 并跳过色度 NR）；DNG 保持 100% 无损彩色 Bayer RAW 并写 IFD0 `0x010E`（`"C3M1 B&W"` / `"C3M1 B&W HI"` / `"C3M1 B&W RED"`）与黑白嵌入缩略图；回看解析单文件 `0x010E` 还原对应黑白影调与单通道高感降噪，且 `c3m1_jdec` 原生支持 `Nf=1` 灰度 JPEG 1X / 4X / CLIP / INFO（标注 `JPEG GRAY`）。
