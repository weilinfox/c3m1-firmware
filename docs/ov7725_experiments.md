# OV7725 RAW 模式片内压扩、黑电平温漂与机内多帧 HDR 实机实验记录

本文档记录在 **C3M1 (C3MarkI) 量产硬件** 上进行的关键底层画质、显示与电源实测实验（原始测试 DNG 文件不入库，可通过对应实验 commit 复现，并配合 `scripts/` 下分析脚本复算）：

1. **实验一**：OV7725 片内 10-bit → 8-bit Gamma 压扩可行性与真 10-bit 域证明（实验 commit `1e1efaf` / 回退 `4e06fbb`）
2. **实验二**：OV7725 片内硬件 ABLC（`COM13`）冷机 vs 热机黑电平温漂标定（实验 commit `46ba9e8` / 回退 `d20b845`）
3. **实验三**：机内 `12B 2F` / `14B 3F` / `16B 4F` 多帧流式 HDR 动态范围与信噪比实拍对比（固件 commit `7990b33`）
4. **实验四**：取景斜纹撕裂机理与 ST7789V3 刷新率 / 消隐同步实机对比（固件 commit `22b080b`）
5. **实验五**：电池满电带载 vs 休眠轻载实测电压与双电量曲线标定（`Core/Src/adc.c`）
6. **实验六**：C3M1 原装定焦镜头几何畸变标定、光学中心偏心分析与 DNG 1.4 `OpcodeList3 (0xC74E)` 实测验证（固件 commit `216dcac`）

### 数据来源约定
为明确各项数值的可信度与可复现方式，本文档各实验均按三类来源清晰区分：
- **`[实测]`**：直接在 C3M1 真机硬件/环境上观测或读取的原始数据（如真机实拍 DNG、机内 ADC 电压读数、HUD 帧率读数、室温计读数、真机目视观感、ACR 验片结果）。
- **`[脚本统计]`**：由分析脚本（`scripts/*.py` 或 Python 离线分析脚本）对真机实拍 DNG 原始像元数据统计、拟合得到的客观计算值。
- **`[估算/理论]`**：未经专用仪器（如电流表、示波器、标准平场积分球）直接测量，而是由芯片手册公式、原理图功耗预算、单点外推或经验曲线插值得到的数值。

## 实验一：OV7725 片内 10-bit → 8-bit Gamma 压扩验证

### 1.1 实验目的与方法
验证 OV7725 在 VGA RAW 输出模式下能否启用片内分段线性 Gamma（`GAM1..GAM15` + `SLOP`），并判断该 Gamma 究竟作用在 **10-bit ADC 线性域**（可救回 8-bit 截断丢失的暗部低 2 bit）还是仅作用在 **8-bit 域**（会出现直方图梳状空洞）。

- **实验固件**：`git cherry-pick 1e1efaf`（按一次快门在完全锁定曝光下连续输出 `GAM_G0.dng` ~ `GAM_G6.dng` 共 7 组寄存器组合）。
- **分析脚本**：[scripts/analyze_gamma_exp.py](../scripts/analyze_gamma_exp.py)
  ```bash
  python3 scripts/analyze_gamma_exp.py <含 GAM_G*.dng 的目录> --export-dng GAM_G4_linearized.dng
  ```
- **数据来源**：`[实测]` 真机拍摄 `GAM_G0..G6.dng`、文件体积 `310 KB`、Adobe Camera Raw 实开验片；`[脚本统计]` 下表全图均值、四通道均值、`G4` 中位数、直方图 `hist[0..24]`、42 级灰阶统计与反表还原均值（均由 `scripts/analyze_gamma_exp.py` 计算）；`[估算/理论]` 理论分段输出列及 `G0` 截断低 2 bit 均值偏移 `+0.375 × 2.5 ≈ +0.94`。

## 实验二：OV7725 片内 ABLC（`COM13`）冷机 vs 热机黑电平温漂标定

### 2.1 实验目的与方法
OV7725 上电默认 `COM13 (0x3E) = 0xE2`（片内光学暗像元自动黑电平校准），而原厂 RAW 配置将其写为 `0x00`（全部关闭）。本实验在严实遮光条件下，分别采集 **18.4°C 冷机（`test_blk_0`）** 与 **连续开机并升温后的热机（`test_blk_1`）** 暗帧，对比 `COM13 = 0x00` 与 `COM13 = 0xE6`（`Bit7/6/5/2` 全开）的暗电流漂移与通道一致性。

- **实验固件**：`git cherry-pick 46ba9e8`（按一次快门在全黑环境下连续拍 6 张 310 KB 自动还原 DNG，均在 10-bit 线性域 `0..1016` 统计 640×480 有效区四通道）。
- **分析脚本**：[scripts/analyze_blc_exp.py](../scripts/analyze_blc_exp.py)
  ```bash
  python3 scripts/analyze_blc_exp.py test_blk_0 test_blk_1
  ```
- **数据来源**：`[实测]` 冷机环境温度 `18.4°C`、真机冷/热机全黑暗帧与 `CDI00570.dng` 实拍、ACR `+5 EV` 复测验片；`[脚本统计]` 下表及 2.3 节各通道均值/`med`/`std`/`zero%`/温漂差（由 `scripts/analyze_blc_exp.py` 及 Python 离线脚本统计）；`[估算/理论]` 12-bit 动态黑电平公式 $`\text{BL}_G = 21 + 4\times\text{gain}_x`$ 与 $`\text{BL}_{RB} = 19 + \lfloor 4.5\times\text{gain}_x\rfloor`$ 系由 `ISO 100 (1×)` 与 `ISO 1600 (16×)` 两端脚本统计结果两点线性拟合得到，中间档位（`ISO 200 / 400 / 800`）为线性插值估计。

> 注：该次临时实验脚本中 `1S_100` 紧接在 `50_1600` 之后仅等待 2 次 VSYNC（少于正式慢门流程的 3 次），因此 `BLC_*_1S_100` 实际复测了 `ISO 1600` 稳定后的第二帧（可作为 `ISO 1600` 稳态对照）。

### 2.3 核心结论与工程参数
1. **原厂关闭 BLC（`COM13 = 0x00`）存在严重热机高 ISO 温漂**：冷机 `ISO 1600` 下 `G` 通道 70% 被截断为 `0` 且 `R/B` 偏高导致暗部发紫；热机后更恶化至 `G ≈ 82`、`R = B ≈ 126`（吞噬 ~12% 动态范围并产生严重洋红暗部雾霾）。
2. **开启片内硬件 ABLC（`COM13 = 0xE6`）彻底稳住暗电流温漂**：硬件光学暗像元在 10-bit Gamma **之前**完成减除，冷热温漂从 `+120` LSB 压缩到 **`±1.5` LSB 以内**，且 `G0/R/B/G1` 四通道完全均衡无偏色。
3. **动态黑电平标定模型（升级至 12-bit 精度 `0..4064`，消除极端拉曝光偏绿）**：
   - 在 10-bit 整数域下用统一 `BlackLevel = (6, 6, 6, 6)` 实拍 `ISO 100` 全黑暗帧（`CDI00570.dng`）时，四通道均值实测为 `G0=6.20, R=5.82, B=5.81, G1=6.25`：`G` 略高于 `6`（`+0.22`），而 `R/B` 略低于 `6`（`-0.18`，在有符号扣黑后归零），导致在 Camera Raw 里极端拉 `+5 EV` 时呈现轻微绿雾。
   - 将 `LinearizationTable` 整体放大 4 倍至 **12-bit 精度（`0..4064`，`WhiteLevel = 4064`，0.25-LSB 精细度，不增加 1 字节 DNG 体积）** 后，全部 6 组冷/热/实拍样本的四通道均值呈现稳定规律：
     - `ISO 100 (1×)`：`G ≈ 24.8`，`R/B ≈ 23.4`（`G - RB ≈ +1.0`）
     - `ISO 1600 (16×)`：`G ≈ 86`，`R/B ≈ 91`（`G - RB ≈ -4.5`）
   - 最终采用分通道动态模型（按 `GRBG` 写入 Tag `0xC61A` 并同步用于取景 LUT 与 AE/AWB）：
     - $`\text{BL}_{G} = 21 + 4 \times \text{gain}_x`$（`ISO 100 → 25`，`ISO 1600 → 85`）
     - $`\text{BL}_{RB} = 19 + \lfloor 4.5 \times \text{gain}_x \rfloor`$（`ISO 100 → 23`，`ISO 1600 → 91`）
   - 经 `CDI00570_neutral.dng` 在 Adobe Camera Raw `+5 EV` 复测验证，暗部绿雾彻底消失。

### 2.4 稳态高 ISO / 高快门复标定修正（`v0.1.16+`）
- **复现与发现**：实验二原突发脚本在 `ISO 100 → ISO 1600` 切换后仅等待 8 帧（`~180 ms`），彼时 `COM13 = 0xE6` 硬件 ABLC 闭环尚未完全收敛（均值停在 `86–91 ADU`）。实拍 `~2700K` 暖光电梯厅对照（`CDI01171` `1/2s ISO 125` vs `CDI01170/1172/1173` `1/25s ISO 1600`）发现高 ISO 成片明显发黄绿；随后用正式固件在严密遮光下**静置 3 秒**实拍稳态 `ISO 1600` 全黑暗帧复测：
  - **`1/50s, ISO 1600`（`CDI01252.dng`）**：`G0/G1` 中位数 `53`（均值 `57.8`，归零率 `15.8%`，反推未截断高斯中心 `μ ≈ 51`），`R/B` 中位数 `64`（均值 `63.3`，归零率 `12.9%`，`μ ≈ 57`）；
  - **`1/4000s, ISO 1600`（`CDI01251.dng`）**：`G0/B/G1` 中位数 `48`（均值 `51`，归零率 `19.5%`，`μ ≈ 44`），`R` 中位数 `53`（均值 `57.7`，`μ ≈ 50`）。
- **修正落地**：原斜率在 `ISO 1600` 过扣 `+34 ~ +47 ADU`（在暖光弱蓝通道上直接砍掉 ~30% 信号），叠加原 `AUTO WB` 蓝增益上限卡死在 `680 (2.65×)` 导致发黄绿。现将 12-bit 稳态动态黑电平修正为：
  - $`\text{BL}_{G} = 23 + \lfloor (3 \times \text{gain}_x + 1) / 2 \rfloor`$（`ISO 100 → 25`，`ISO 800 → 35`，`ISO 1600 → 47`，`ISO 3200 → 70`）
  - $`\text{BL}_{RB} = 21 + \lfloor (7 \times \text{gain}_x + 2) / 4 \rfloor`$（`ISO 100 → 23`，`ISO 800 → 35`，`ISO 1600 → 49`，`ISO 3200 → 75`）
  并同步将 `AUTO WB` 蓝增益上限放宽至 `1024 (4.00×)` 及增加 `g_exposure_dirty_frames == 0U` 守卫（离线复测 `CDI01172` 白墙/暗影 `B/G` 从 `0.597 / 0.451` 恢复至 `1.006 / 0.927`）。

## 实验三：机内 `12B 2F` / `14B 3F` / `16B 4F` 多帧 HDR 动态范围实拍对比

### 3.1 实验条件与方法
- **验证固件**：commit `7990b33`（`v0.1.11` + `16B 4F`），`ISO 100` 三脚架固定大光比室内桌面场景（顶部高亮度冷白 LED 灯条 + 暗部黑色键盘/机身边框）。
- **测试分组**（共 22 个 DNG）：
  - **场景 1（基准快门 `1/100s`）**：单帧 10-bit（`CDI00704`）、`12B 2F`（`CDI00705`）、`14B 3F`（`CDI00707`）、`16B 4F`（`CDI00710`）。

- **噪声与动态范围度量**：在相同 150 个 `8×8` 暗部块及最平滑 5% 暗块内，以同行相邻同色绿像素差分 $`\sigma_G = \sqrt{\frac{1}{2N}\sum (G_{x+2} - G_x)^2}`$ 估算实测噪声底，计算有效动态范围 $`\mathrm{DR} = \log_2(\mathrm{WhiteLevel}_{\text{eff}} / \sigma_G)`$ 与同暗区信噪比 $`\mathrm{SNR} = 20\log_{10}(\mu_G / \sigma_G)`$。

  - `[脚本统计]`：下表同暗区中位 SNR、有效 DR、峰值像素、高光死白率，以及 `CDI00704.dng` / `CDI00710_3.dng` 绿通道平滑 `8×8` 块局域方差斜率（$`\Delta\mathrm{Var}_{12}/\Delta\mu_{12} \approx 0.223`$），均由 Python 离线分析脚本对实拍 DNG 像元直接统计得到。
  - `[估算/理论]`：由单图平滑块方差斜率反推的转化增益 $`K_{12} \approx 4.5\ e^-/\text{ADU}_{12}`$ 与 $`\text{FWC}_{\text{ISO 100}} \approx 18,000\ e^-`$（尚未通过均匀白墙双帧差分消除 PRNU，系结合 OV7725 手册标称 `17,000–26,000 e⁻` 交叉印证的估算值）；[architecture.md §3.12](./architecture.md) 中其余 ISO 与多帧 HDR 满阱电子数均为基于该单点估算按公式外推；极暗夜景 `16B 4F` 增量趋近 `+1.8 ~ +1.9 EV` 亦为理论外推。

### 3.4 关键结论
1. **逐档动态范围增益符合传感器物理规律**：
   - `10-bit → 12B 2F`：暗部读出噪声主导，暗部 SNR 实涨 `+6.06 dB`（`+1.01 EV`）+ 高光 `+1.00 EV`，总有效 DR 实涨 **`+1.84 EV`**；
   - `12B 2F → 14B 3F`：高光再增 `+1.03 EV`，暗部进入散粒噪声过渡区（`+3.68 dB`），总有效 DR 再涨 **`+1.51 EV`**；
   - `14B 3F → 16B 4F`：理论容器跨度再增 **`+1.94 ~ +2.00 EV`**（`16× → 64×`），实拍高光实得 **`+0.96 EV`**（场景 2 将 `14B 3F` 仍残留的 `0.88%` 灯条死白完全拉回至 `0.00%` 并余留 `0.37 EV` 余量），暗部在散粒噪声主导区再增 **`+3.55 dB`（`+0.49 EV`）**，常规室内实测总有效 DR 净增 **`+1.21 ~ +1.45 EV`**（`1/100s` 组实测达 **`14.13 ~ 14.60 EV`**）；极暗夜景等读出噪声主导场景下暗部增益可进一步逼近满额 `+1.0 EV`（总增量趋近 `+1.8 ~ +1.9 EV`）。
2. **`WhiteLevel = 65535` 饱和边界表现正常**：OV7725 实测相邻帧有效增益比略高于名义 `4.00×`（约 `4.10×`，三步连乘约 `69×`），`1009 × 69` 触发 `UINT16_MAX = 65535` 钳位（仅裁掉 `-3 EV` 最顶部约 `0.09 EV`），`BaselineExposure` 仍精确锚定 `+2.99 ~ +3.00 EV`，全图无溢出、无色偏、无接缝。
3. **OV7725 实机有效满阱容量估算（供 JSR 超分噪声模型配置）**：对 `CDI00704.dng` 与 `CDI00710_3.dng`（`ISO 100`，`WL_eff = 4039`）绿通道平滑 `8×8` 块统计局域方差斜率（扣除读出噪声后 $`\Delta \mathrm{Var}_{12} / \Delta \mu_{12} \approx 0.223`$），估算转化增益 $`K_{12} \approx 4.5\ e^-/\text{ADU}_{12}`$、有效满阱容量 $`\text{FWC}_{\text{ISO 100}} \approx \mathbf{18,000\ e^-}`$（与 OV7725 手册标称 `17,000–26,000 e⁻` 高度一致）；不同 ISO 与多帧 HDR 合成后的完整等效电子数换算见 [architecture.md §3.12](./architecture.md)。

## 实验四：取景斜纹撕裂机理与 ST7789V3 刷新率 / 消隐同步实机对比

### 4.1 现象与成因
- **实机现象**：平移相机时取景画面出现稳定的斜向分层撕裂（基线 60 Hz 下 `1X` 约 4 层，`4X` 约 1 层）。
- **物理根因**：
  1. **90° 扫描正交**：2.0" `ZJY200K-IF09`（`ST7789V3`）原生为 `240×320` 竖屏玻璃，硬件 Gate 驱动沿 320 长边扫描；横屏显示（`320×240`, `MADCTL MV=1`）时，屏幕刷新方向为**水平左右扫**，而 MCU 取景渲染为**垂直逐行写**（`y = 0 → 239`）。两条互相垂直的扫描前沿交汇轨迹即为斜线。
  2. **硬件架构硬约束**：彻底消除正交撕裂需全帧 SRAM 双缓冲（`320×240` RGB565 需 `150 KB`，远超 STM32F103ZET6 `64 KB` SRAM 且 ST7789V3 无双页 GRAM）或把整帧读取+解码+写屏压入 LCD V-Blank（`≤ 12–18 ms`），而 72 MHz 下仅 GPIO 读/跳过 AL422B 309 KB RAW 即超 `20 ms`。

### 4.2 三组实机对照测试（同一硬件 `ST7789V3` + `OV7725`）
- **数据来源**：`[实测]` 各组实机 HUD 帧率读数（`~10 / 7 fps`）与平移相机目视撕裂层数/观感；`[估算/理论]` “理论刷新率 / 周期”（`~59.3 / 109.3 / 40.8 Hz`）、`8.8 ms` V-Blank、TFT 充电时间缩短 `46%` 均由 ST7789V3 数据手册标称 `10 MHz` 内部振荡器与 `FRCTRL2`/`PORCTRL` 寄存器公式推导（未用示波器实测面板帧同步频率），`>20 ms` GPIO 读 FIFO 下限为基于 72 MHz 指令周期估算。

| 实验组 | ST7789V3 配置与软件改动 | 理论刷新率 / 周期 `[估算/理论]` | 实测帧率（`1X / 4X`）`[实测]` | 实机主观观感与撕裂层数 `[实测]` |
| :--- | :--- | :---: | :---: | :--- |
| **基线（最终保留）** | `FRCTRL2 (0xC6) = 0x0F`, `PORCTRL (0xB2) = 0x0C/0x0C`（原厂 490 clks/line） | `~59.3 Hz` / `16.9 ms` | `~10 / 7 fps`（室内） | **`1X` 约 4 层，`4X` 仅 1 层**；综合观感最自然稳定，面板对比度正常 |
| **方案 1（高频高刷）** | `FRCTRL2 (0xC6) = 0x01`（266 clks/line） | `~109.3 Hz` / `9.15 ms` | `~10 / 7 fps` | 单条斜纹略变细，但一帧内被横扫次数翻倍，**时间刷新层纹明显加重、`4X` 观感显著变差**（且每行 TFT 充电时间缩短 46%） |
| **方案 2（热循环提速叠加）** | 在方案 1 上叠加 `raw_demosaic` `noinline/O3` + 融合 `USAT` + 32-bit `__REV16` 写 + 去 `FIFO_SKIP_1` `__NOP()` | `~109.3 Hz` / `9.15 ms` | `10 / 7 fps` | 仅轻微改变切分节拍，未能抵消高频层纹，观感仍不如原版 60 Hz |
| **方案 3（降刷长消隐 + 扫描线同步）** | 恢复 `0xC6 = 0x0F`，`PORCTRL (0xB2) = 0x5A/0x5A`（90/90 Porch，8.8 ms V-Blank）+ 帧首 `0x45 (GSCAN)` 等待进入消隐期 | `~40.8 Hz` / `24.5 ms` | `~10 / 7 fps` | 仅改变了撕裂层数分布，**相对原版 60 Hz 无明显观感提升**，且 `4X` 不如原版单层干净 |

### 4.3 结论
- **不合入代码改动，固件保持原厂 `60 Hz`（`0xC6 = 0x0F`, `0xB2 = 0x0C/0x0C`）配置**：在无全帧双缓冲且 $`T_{\text{paint}} > T_{\text{lcd}}`$ 的前提下，单纯调整 ST7789V3 刷新率或引入 `GSCAN` 消隐同步仅改变撕裂层数切分，无法带来实质性观感改善；原版 60 Hz 下 `1X`（~4 层）与 `4X`（1 层）反而是当前硬件条件下的最佳平衡点。

2. **典型锂电 U 型内阻分段双曲线（取代原固定 `+50 mV` 偏移）**：24 组稳定工作→立即休眠实测完整揭示了单节锂电池的 **U 型直流内阻特征**——高电端（`≥ 3.91V`，含 `3.91/3.94V` 切低功耗即回升 `+20 mV`）与低电端（`≤ 3.45V`）压差均为 **`+50 mV`**，而中段放电平台（`3.50–3.84V`，`30%–80%`）直流内阻最低、压差稳定收窄至 **`+30 mV`**。`adc_mv_to_percent_light()` 改为独立 11 点标定表（全段实测误差 `≤ ±1%`、中位误差 **`0%`**）：
   - **工作带载曲线 `adc_mv_to_percent()`**：`3250 / 3380 / 3490 / 3550 / 3590 / 3630 / 3680 / 3740 / 3820 / 3910 / 4000 mV`（`0%..100%`）
   - **休眠轻载曲线 `adc_mv_to_percent_light()`**：`3300 / 3430 / 3530 / 3580 / 3620 / 3660 / 3710 / 3770 / 3850 / 3960 / 4050 mV`（`0%..100%`，两端 `+50 mV`、`20%` 过渡 `+40 mV`、`30%–80%` 中段 `+30 mV`）
3. **休眠速览配色与低电恢复阈值对齐**：
   - `sleep_show_battery_peek()` 使用 `adc_mv_to_percent_light()` 并以 `≤ 25%`（黄）、`≤ 16%`（红）对齐工作态 `3.52V / 3.45V` 预警边界（实测 `3.45/3.50V` 同为黄、`3.44/3.49V` 同为红），消除工作与休眠之间的百分比及颜色跳变；
   - 低电休眠插电重启实测 `3.53/3.57V`，将亏电休眠自动切回普通休眠的阈值设为 **`BAT_RECOVER_PCT = 25%`**（对应轻载 `~3.56 V`，`3.57 V` 显示 `28%` 稳定达标并留有 `≥ 360 mV` 滞回）。

## 实验六：C3M1 原装定焦镜头几何畸变标定与 DNG `OpcodeList3 (0xC74E)` 验证

### 6.1 实验目的、方法与数据来源
验证 C3M1 原装等效 50mm 定焦手动镜头在不同物距下的几何畸变特性，标定固件 DNG 1.4 `OpcodeList3 (0xC74E)` 单平面 `WarpRectilinear`（$`r_{\text{src}} = r(k_{r0} + k_{r1} r^2)`$，归一化半径 $`m = \sqrt{320^2 + 240^2} = 400\text{ px}`$，默认居中中心 `(0.5, 0.5)`）的最佳 `kr1` 参数，并在 Adobe Lightroom Classic / Camera Raw 中实机验片。

- **测试样本**（6 张 C3M1 真机实拍 DNG，不入库）：
  - 远景 `CDI00623.dng`（~20 m+，桥面水平护栏与竖直灯杆）
  - 中远景 `CDI00621.dng`（~10 m，路面标线与路缘）
  - 中距 `CDI00629.dng`（~3–5 m，公交站台左右整高立柱）
  - 近距 `CDI00628.dng`（~0.3 m，汽车头枕竖直金属柱）
  - 近距标准矩形框 `CDI00817.dng`（笔记本四边边框）与 `CDI00819.dng`（高反差大显示器上下白边 + 左右黑边，四边对称覆盖画面四周）
- **数据来源**：
  - `[实测]`：全部 6 张真机实拍 DNG，以及将不同候选 `kr1`（`-0.02 .. -0.10` 与 `+0.04/+0.08`，步进细至 `0.001`）注入标准 DNG `OpcodeList3 (0xC74E)` 后在 Adobe Lightroom / Camera Raw 中的逐档肉眼对比结论（确认 `0xC74E` 自动生效、识别 `-0.080..-0.090` 过矫偏枕形、识别上下边缘畸变不对称、选定甜点 **`kr1 = -0.072`**）。
  - `[脚本统计]`：Python 离线 Plumb-line 直线拟合脚本基于实拍 DNG 亚像素边缘提取计算的各条直线与联合拟合 `kr1`、矫正前后直线 RMS 残差、二阶 `kr2` 检验及自由光学中心 `(cx, cy)` 拟合值。
  - `[估算/理论]`：视野留存百分比及 `kr0 = 1 - 0.36·kr1` 最大内接无黑边缩放的几何推算；物距从 `∞` 调焦至 `0.5 m` 像距伸出量 `< 0.08 mm`（按实焦 $`f \approx 5\text{–}6\text{ mm}`$ 薄透镜公式估算）。

### 6.3 关键发现与固件落地
1. **定位并修复了 DNG `OpcodeList3` Tag 号 Bug**：早期固件误写为 `0xC742`，导致 Lightroom / Camera Raw 完全忽略；依据 DNG 1.3/1.4 规范修正为 **`0xC74E`（51022）** 后，Lightroom 与 Camera Raw 打开 DNG 即自动应用畸变矫正。
2. **揭示了上下畸变不对称的物理根因（镜头装配偏心）**：
   - Lightroom 肉眼对比与 `CDI00819.dng` 四框脚本拟合高度一致：上白边单独拟合仅 `-0.0524`（`0.086 px` RMS），而下白边高达 `-0.0963`（`0.096 px` RMS）；释放光学中心后拟合出 **`(cx, cy) ≈ (280, 200)`**，四框总残差直接减半至 `0.214 px`，且此时真实径向系数恰为 **`kr1 = -0.0721`**。
   - 这也完美解释了为何早期仅靠画面下半部护栏/路面标线（`CDI00623` / `CDI00621`）按居中 `(320, 240)` 拟合时偏高至 `-0.087 ~ -0.090`，在全画面目视下出现轻微过矫枕形，而全画面综合甜点精准落在 **`kr1 = -0.072`**（`[实测]` Lightroom 肉眼定标 `-0.072` 与 `[脚本统计]` 自由中心拟合 `-0.0721` 吻合至 `0.0001`）。
3. **最大内接无黑边缩放 `maxfov` 对比验收（`kr1 = -0.072`）**：
   - 在全部 6 张实拍样本上以 Lightroom / Camera Raw 实测对比 `kr0 = 1.0` 与 `maxfov`（4:3 画面上下边中点 $`r^2 = 0.36`$，桶形畸变取 $`k_{r0} = 1 - 0.36 k_{r1} = 1.02592`$；枕形畸变取 $`k_{r0} = 1 - k_{r1}`$）：

| 方案（`kr1 = -0.072`） | 上下边中点视野留存 `[估算/理论]` | 左右边中点视野留存 `[估算/理论]` | 四角对角线留存 `[估算/理论]` | Lightroom / ACR 实测观感 `[实测]` |
| :--- | :---: | :---: | :---: | :--- |
| 普通缩放（`kr0 = 1.0000`） | `97.4%`（上下各裁 `6.2 px`） | `95.4%`（左右各裁 `14.7 px`） | `92.8%`（对角裁 `28.8 px`） | 直线拉直，但上下左右边缘裁切感较明显 |
| **`maxfov`（`kr0 = 1.0259`）** | **`100.0%`（上下 0 裁切）** | **`98.0%`（左右仅裁 `6.5 px`）** | **`95.4%`（对角裁 `18.4 px`）** | **视野明显更宽、像素损失减半、四周完全无黑边，选定合入固件** |

4. **固件菜单与配置细化（`c3m1.cfg` schema v14 → v16）**：
   - 将 `LENS DIST` 步进由 `0.01` 细化为 **`0.002`**（范围 `-0.200 .. +0.200`，仍占原 `1 B` `int8_t`，无损迁移 v13 配置），使实机可直接精准设定 **`-0.072`**；
   - `c3m1_dng.c` 的 `WarpRectilinear` 默认启用 `maxfov` 内接缩放（$`k_{r1} < 0`$ 时 $`k_{r0} = 1 - 0.36 k_{r1}`$，$`k_{r1} > 0`$ 时 $`k_{r0} = 1 - k_{r1}`$），在零黑边前提下最大限度保留 640×480 边缘像素；
   - 保持居中 `(0.5, 0.5)` 以兼顾不同机身装配偏心公差（单机实测发现已同步记入批次漂移核对清单）；暗角 `LENS VIG` 保持 `0.05` 步进（对应四角约 `0.024–0.07 EV`/格），标定结果详见下方实验 7。
5. **机内实时矫正（1X 监看 & 直出 JPEG）与取景热循环实测性能及已知权衡（`[实测]`）**：
   - 初版机内畸变（4× 完整 3×3 解马赛克 + 逐像素非线性重采样，未并行 DMA1）在 STM32F103ZET6 上实测 1X 监看 **`7 fps`**、直出 JPEG 编码写卡耗时 **`6 s`**；
   - 第一轮优化（`272ee41`：JPEG 改为 MCU 四角分段双线性步进 + 单遍 12 次查表 Bayer 通道/菱形绿晶格双线性与零 `% 50` 除法；1X 监看改为 20 段 16 px 分段线性无分支半字拷贝 + DMA1 行发送期并行预取 AL422B）后，实测 1X 开启/关闭畸变均为 **`8 fps`**、`4X` 为 **`6–7 fps`**，直出 JPEG 速度亦明显改善；
   - 第二轮取景热循环优化（`871c5a4`：1.75× 色度增强代数化简并融合 Cortex-M3 单周期 `USAT ASR` + 32-bit `REV16` 双像素写、去冗余 `FIFO_SKIP_1` `__NOP()`、`fifo_read_r_320` / `raw_demosaic_320_sampled` / `vf_apply_focus_peaking` 4× 展开与无跳转主路径、HUD 32-bit SWAR 暗化，0 新增 `.bss`）后，实机复测帧率进一步提升至：**`1X (INCAM DISTORT = OFF)` `9–10 fps`**、**`1X (INCAM DISTORT = ON)` `8 fps`**、**`4X` 原生 1:1 放大 `8 fps`**（`4X` 较前版 `6–7 fps` 明显顺滑）；
   - **1X 监看“错位边界”现象记录（`[实测]`）**：开启机内实时畸变后，1X 监看画面中靠近边缘的直线可明显看到 **2 px 高的水平阶梯状错位边界**。成因是 1X 取景为保流畅底层采用 `320×120` 逐对行渲染（纵向 2× 复制至 `320×240` LCD）并配合最近邻重采样，每当拉直映射跨过一行源行对即产生 2 LCD 像素的离散跳变；该现象仅存在于 1X 监看预览，不影响采用双线性插值的直出 JPEG 与 DNG 嵌入缩略图，更不影响无损 DNG RAW；
   - **独立机内开关 `INCAM DISTORT`（schema v16，位于 `LENS VIG` 下方，默认 `OFF`）**：关闭时仅向 DNG 写入 `OpcodeList3 (0xC74E)` 矫正信息，1X 监看、直出 JPEG 与缩略图均不做几何重采样；后续叠加 U1 行间抗锯齿优化（`15b824c`）与 64 级融合暗角优化（`9a0b1e3`）后，实机 **`INCAM DISTORT (ON/OFF) × ANTI-ALIASING (ON/OFF)` 全部组合在 `LENS VIG = +1.15` 下均稳跑 `9–10 fps`**（`4X` 维持 `8 fps`）。

## 实验 7：标配 6mm f/1.6 镜头平场暗角标定与 `FixVignetteRadial` 定标

- **数据来源**：`[实测]` 标配 6mm f/1.6 镜头实拍平场 DNG 对照组（裸拍显示器白屏 `CDI00994/996/997`、白墙/纸面 `CDI00995/999`、白屏垫纸漫射全对焦行程 4 组 `CDI01001–01004`、`LENS VIG = +1.05` 复测 4 组 `CDI01005–01008`、`LENS VIG = +1.15` 复测 4 组 `CDI01009–01012`）；`[脚本统计]` 线性化（查 `0xC618` 扣 `BL`）后按 32×32 分块 70% 分位避开格线，并联合 2D 线性光照倾斜与 DNG 1.4 `FixVignetteRadial`（$`g(r) = 1 + k_0 r^2`$，$`r = \sqrt{(x-320)^2 + (y-240)^2} / 400`$）最小二乘拟合，同时在叠合 `WarpRectilinear (kr1 = -0.072, kr0 = 1.02592)` 后的最终输出画幅上评估径向平整度。

### 7.2 叠合 `WarpRectilinear (-0.072)` 后的 `k0 = +1.05` vs `+1.15` 验收

- 色彩暗角核查：全组漫射样本在 `r = 0.97` 处 `R/G` 仅降 `2–4%`、`B/G` 仅升 `4–5%`，说明无需独立 RGB 分通道暗角表，单通道共享 `FixVignetteRadial` 即可满足精度要求。
- 叠合实机 `WarpRectilinear (kr1 = -0.072)` 裁切极角（$`r > 0.954`$）后的最终成片径向平整度对比（`CDI01007 / 1008` 线性 `G/G0`，`r = 0.05 → 0.95`）：
  - **`k0 = +1.05`（21 格）**：`r = 0.55–0.75` 中外圈仍残留 `-4% ~ -5%`（`0.95–0.96`）轻微发暗环；
  - **`k0 = +1.15`（23 格）**：`r = 0.05–0.85` 全部压平至 **`0.98 ~ 1.01`**（`±1–2%`），中外圈发暗环彻底消失，最角尖 `r = 0.95` 线性仅 `+7%`（sRGB 约 `+3%` 肉眼无感），且与无穷远平场实测 `+1.14` 及 `CDI01009–01012` 实拍目视验收一致。
- **固件落地**：将 [c3m1_cfg.c](../Core/Src/c3m1_cfg.c) 中 `6mm F1.6` 镜头预设的 `.vignette` 由 `0U` 更新为 **`23U`（`+1.15`）**；选中 `6mm F1.6` 预设时自动联动 `FOCAL=6mm / F1.6 / DIST=-0.072 / VIG=+1.15`，仍支持用户在菜单中按需手动微调或关闭。
